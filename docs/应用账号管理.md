# 应用账号管理

入口：`https://<VM>:8443/admin/accounts`

该页面只管理研究平台应用账号。应用超管可以新增账号、修改应用权限、启用或停用账号、重置其他账号的密码，以及删除账号。权限、状态或密码变化时，该账号的全部既有会话会立即失效。删除采用保留审计记录的软删除，账号名不能被静默复用。

“应用超管”不是 Windows 管理员、VM 管理员或 PostgreSQL 超级用户。Viewer 不提供命令、文件写入、服务、计划任务、数据库角色或迁移入口。原 `/refresh/<industry_id>` 网页命令执行入口已经移除，页面仅保留只读差异展示。

## 首位超管与密码找回

迁移只登记已有的 `research-operator` 为首位应用超管，不创建 `wubowen`，也不设置默认密码。首位超管沿用原 Windows Credential Manager 登录凭据。

如需初始化或找回首位超管密码，必须登录 VM，在当前不可变 release 中运行本机窗口：

```powershell
python -m tools.migration.application_superadmin_local --runtime <生产 PostgreSQL runtime.json 的绝对路径>
```

窗口中的密码默认遮罩，可勾选“显示密码”。密码不经过聊天、命令参数、环境变量、项目文件或日志；工具只向 PostgreSQL 写入版本化 scrypt 哈希，并撤销全部旧会话。该本机入口只能重置已经存在且仍启用的应用超管，不能创建 Windows、VM 或数据库账号。

## 生产部署闭包

账号域不能拆成“先迁移、以后再补登录证明”的多步人工流程。必须在 VM 的批准交互式身份下运行统一入口：

```powershell
python -m tools.migration.provision_application_identity_production `
  --repo-root <不可变 release> `
  --runtime <生产 runtime.json> `
  --security-config <不可变 release>/config/migration/user_content_security_production.json `
  --output <生产 evidence>/application-identity-provision.json
```

该入口依次完成：强制收敛专用数据库角色权限和日志策略、仅在缺失时创建独立 WinVault 密钥、精确应用 `0026`、绑定 VM 登录证明、核验白名单函数和数据库权限。任何一步失败都不会把未完成状态写成通过证据。

密码幂等密钥按 `v1` 冻结。普通安全配置重跑会保留既有密码幂等密钥和登录证明，不允许无提示覆盖。确需轮换登录证明时，必须使用受控 finalizer；轮换会写入不含密钥或哈希的安全审计并撤销全部应用会话。

## 生产权限边界

- Viewer 使用独立 `honghu_writer_application_identity` PostgreSQL 登录角色。
- 该角色没有表级读取或 DML、DDL、`CREATE`、角色管理或跨域写权限，只能执行账号域白名单函数。
- 密码明文、密码哈希、幂等指纹、登录证明及其哈希不会进入响应、业务审计、幂等结果或部署证据。
- PostgreSQL 为该角色强制 `log_statement=none`、`log_parameter_max_length=0`、`log_parameter_max_length_on_error=0`，避免登录证明进入语句或参数日志。
- 密码操作幂等指纹使用独立 WinVault HMAC 密钥，不复用 Flask 会话签名密钥；三组密钥身份在运行时必须完全不同。
- 登录完成还要求 VM WinVault 中的独立认证证明；仅泄露 PostgreSQL 应用 writer 凭据不能绕过验密铸造会话。
- 管理操作需要 HTTPS、有效服务端会话、同源校验、CSRF、近期重新登录、幂等键和目标账号版本。
- 当前超管不能自删、自停用或自降权；数据库事务保证任何时刻至少保留一名启用的应用超管。
- 登出即使遇到数据库故障，也会先清除浏览器本地会话；服务端撤销失败会作为受控错误记录，不会把旧 Cookie 留在浏览器等待数据库恢复后复活。
