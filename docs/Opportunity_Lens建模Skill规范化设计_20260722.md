# Opportunity Lens 建模 Skill 规范化设计

版本：2026-07-22  
状态：修订版设计建议，尚未成为活动工作流合同  
适用范围：`industry_demo` 的 C 轨 Opportunity Lens 研究

## 1. 修订后的结论

上一版建议的 Skill 太多，把“研究时应当考虑的逻辑链”误当成了“必须用严格模板约束的专业方法”。重新按更严格标准筛选后，真正需要建立严格 Skill 的只有四个：

1. **公司财务建模**；
2. **公司估值建模**；
3. **行业市场空间与供需建模**；
4. **概率与情景建模**。

前两个本来就是已经明确需要建设的财务估值体系。Opportunity Lens 额外需要新增的严格 Skill，实际上只有后两个。

其他内容，例如竞争进入里程碑、技术成熟度、公司敞口映射、监控指标、专利和招聘核验，都很重要，但它们主要是：

- 研究逻辑；
- 证据解释规则；
- 特定行业的参考资料；
- 报告输出要求；
- 确定性检查或测试。

这些内容不值得分别建立顶层 Skill。拆得过细会增加上下文、制造重复规则，并诱导 Agent 每个任务机械套用全部模块。

## 2. 严格 Skill 的准入门槛

一个问题只有同时满足以下条件，才应建立严格 Skill：

1. **存在成熟方法参照**：行业研究、公司金融、决策科学或相关专业领域已经形成较稳定的模型和术语。
2. **包含实质计算或模型选择**：不是提醒 Agent 多想一步，而是必须在若干公认方法中选择并正确计算。
3. **Agent 容易拍数**：没有模板时，容易自行假设市场份额、概率、利润率、估值倍数或远期增长。
4. **错误影响重大**：错误会直接改变市场空间、供需缺口、利润、现金流、估值或结论概率。
5. **可以复算和校准**：输入、公式、输出、敏感性和历史误差可以独立检查。
6. **跨任务复用**：不是某一个专题才成立的临时分析框架。

若一个问题只是要求“证据链完整”“不要从专利跳到量产”“说明证伪条件”，它属于研究规范，不需要单独 Skill。

## 3. 最小化后的严格 Skill 体系

| Skill | 是否已有明确专业参照 | 不做模板时的主要风险 | 是否保留 |
|---|---|---|---|
| 公司财务建模 | 三表、经营驱动、现金流、会计勾稽、预测方法 | 从行业叙事直接拍收入和利润 | 保留 |
| 公司估值建模 | DCF、PE、EV/EBITDA、PB-ROE、SOTP、NAV、反向估值 | 随意选倍数、终值和折现率 | 保留 |
| 行业市场空间与供需建模 | TAM/SAM/SOM、量价模型、库存恒等式、有效产能、供需平衡 | 混单位、重复计算、把规划产能当供给 | 保留 |
| 概率与情景建模 | 参考类别、贝叶斯更新、决策树、情景分析、Monte Carlo、校准 | 主观加点并输出伪精确概率 | 保留 |
| 竞争进入 | 主要是事件定义和证据里程碑 | 从弱证据跳到量产 | 不单建；并入概率 Skill 的事件定义与证据输入 |
| 技术成熟度与替代 | 不同行业标准差异大，统一模板容易失真 | 混淆实验室、样品和量产 | 不单建；使用行业参考资料和现有证据流程 |
| 公司敞口映射 | 是财务建模前置输入，不是独立模型体系 | 主题受益直接当利润受益 | 不单建；并入财务建模 |
| 监控与证伪 | 主要是研究输出和更新机制 | 指标罗列但不能改变结论 | 不单建；保留在报告合同和指标槽设计中 |
| 历史校准 | 是验证工具和测试体系 | 模型长期系统性偏差 | 不单建；作为四个 Skill 的共同测试 harness |
| 专利、招聘、展会核验 | 是来源和证据类型的专业说明 | 把线索写成事实 | 不单建；作为证据参考页 |

## 4. 严格 Skill 一：公司财务建模

### 4.1 为什么必须严格规范

公司财务预测存在成熟的会计和金融建模体系。没有固定方法时，Agent 很容易从行业增速、竞争概率或远期市场规模直接外推公司收入和利润，忽略市场份额、ASP、毛利率、费用、资本开支、营运资金和少数股东损益。

因此它必须是低自由度、可复算的 Skill，而不是几条写作提醒。

### 4.2 核心职责

- 识别公司经济类型和盈利驱动；
- 判断可用数据支持何种模型深度；
- 建立收入、成本、费用、利润和现金流传导；
- 完成三表和关键会计口径勾稽；
- 计算所有适用且数据足够的利润模型；
- 与公司指引和一致预期对账；
- 记录修改前后假设和证据；
- 数据不足时主动降级，不填补虚构数据。

### 4.3 公司敞口并入本 Skill

“公司是否真正受益”不另建 Skill，而是财务建模的经营输入层：

```text
产业机会
→ 公司具体产品和客户
→ 可用产能和订单
→ 分部收入
→ 毛利和费用
→ 净利润与自由现金流
```

必须检查上市主体、子公司和母集团关系，区分直接供货、间接受益、上游受益和主题映射。若无法拆分相关业务收入，只能使用有说明的代理或情景，不能假装拥有产品级数据。

### 4.4 应包含的方法参照

- 数量 × 价格；
- 市场空间 × 公司份额；
- 财务桥接；
- 历史规律和周期正常化；
- 一致预期辅助；
- 反向利润模型；
- 三表、FCFF、FCFE 和营运资金勾稽；
- 订单、产能和收入确认的行业适配。

详细财务字段和数据来源可连接现有 [`公司财务建模可用字段总目录_20260722.md`](公司财务建模可用字段总目录_20260722.md)。

## 5. 严格 Skill 二：公司估值建模

### 5.1 为什么必须严格规范

估值方法具有明确的适用条件和行业共识。没有模板约束时，Agent 容易：

- 对周期顶部利润使用高 PE；
- 对轻资产公司机械使用 PB；
- 随意选择 WACC 和永续增长率；
- 忽略企业价值与股权价值转换；
- 把多个依赖相同假设的结果简单平均；
- 为了贴近研报而反向修改独立预测。

### 5.2 核心职责

- 根据经济类型判断估值方法是否适用；
- 计算全部适用且数据足够的方法；
- 标明核心、参考、诊断和不适用；
- 统一估值日期、预测年份、币种、股本和资本结构；
- 检查终值、折现率、倍数和周期位置；
- 解释多个模型结果为什么一致或冲突；
- 独立估值冻结后，再与一致预期和市场价格对账；
- 用反向估值说明当前价格隐含什么经营条件。

### 5.3 应包含的方法参照

- DCF；
- PE 和正常化 PE；
- EV/EBITDA；
- PB-ROE 与残余收益；
- NAV；
- SOTP；
- DDM；
- 历史和同行估值；
- 反向 DCF 和市场隐含预期。

行业适用性、数据要求和禁用条件放入按需读取的 reference，不在每次研究中全量加载。

## 6. 严格 Skill 三：行业市场空间与供需建模

### 6.1 为什么需要新增

这是 Opportunity Lens 除财务估值外最需要标准化的专业模型。

市场空间和供需研究已有成熟方法：自上而下与自下而上对账、数量乘价格、存量与增量区分、库存恒等式、产能到有效产量的转换、渗透率和单位用量建模。这些不是简单逻辑提醒，而是可计算、可复核的模型体系。

没有严格模板时，Agent 最容易出现以下错误：

- 把设备投资额直接当设备采购额；
- 把系统市场、部件市场和公司收入重复相加；
- 把规划产能、设计产能或厂房建设当成当期有效供给；
- 忽略利用率、良率、认证和爬坡；
- 将装机量、出货量、产量、消耗量和收入混为同一口径；
- 用行业总增速直接外推公司收入；
- 用价格上涨同时证明需求和供给假设，形成循环论证。

### 6.2 适用范围

本 Skill 在以下任务触发：

- 市场规模、TAM、SAM、SOM；
- 产品出货、渗透率和单位用量；
- 供需缺口、库存和价格周期；
- 产能扩张、有效供给和投产节奏；
- 客户资本开支向材料、设备或部件需求传导；
- 行业量价和公司经营模型的产业输入。

纯粹的技术路线讨论、证据综述或公司事件核验不触发本 Skill。

### 6.3 共识模型骨架

#### 市场数量

```text
需求数量
＝终端或系统数量
×渗透率
×单位用量
×替换或新增系数
```

#### 市场金额

```text
市场金额
＝各产品数量 × 对应 ASP 的合计
```

#### 有效供给

```text
有效供给
＝名义产能
×按期投产比例
×产能利用率
×良率
×产品或客户可用比例
－停产与不可售产出
```

#### 库存平衡

```text
期末库存
＝期初库存
＋有效供给
－真实消耗
```

不同产业可以替换变量，但必须保持数量、时间和存量流量关系一致。

### 6.4 强制方法

1. 先定义产品、地理、客户、期间和数量单位；
2. 区分实际、公司目标、外部预测和研究假设；
3. 可行时同时建立自上而下和自下而上两条路径；
4. 检查两条路径的差异来源；
5. 区分存量、增量、替换需求、补库存和去库存；
6. 区分稳定产能、爬坡、试产、在建、规划和传闻；
7. 进行数量 × 单价、产能 × 利用率和单位换算反查；
8. 数据不足时输出区间、阈值或不可量化，不补精确参数。

### 6.5 输出

- 市场数量和市场金额；
- 实际与预测分期；
- 自上而下与自下而上结果；
- 有效供给和库存调整；
- 供需缺口或平衡状态；
- 主要瓶颈；
- 关键假设及来源类型；
- 基准和必要的敏感性；
- 可传递给公司财务模型的经营变量。

### 6.6 行业差异使用 reference，不再拆 Skill

建议只设置按需读取的行业参考：

```text
references/
├─ semiconductor-capacity.md
├─ equipment-project-orders.md
├─ discrete-components-bom.md
└─ commodity-inventory.md
```

它们负责解释晶圆等效产能、设备强度、节点 BOM、商品库存等行业差异，不分别注册为顶层 Skill。

## 7. 严格 Skill 四：概率与情景建模

### 7.1 为什么需要新增

这是 Opportunity Lens 第二个真正需要严格约束的新增 Skill。

当用户询问“3—5 年内进入概率”“至少一家成功概率”“某风险发生概率”或需要把不确定事件传导到财务时，Agent 很容易先给主观百分点，再用 Monte Carlo 生成看似精确的结果。run9 暴露的问题本质上不是缺少一张竞争里程碑表，而是概率方法没有稳定合同。

概率与情景分析有成熟参照：参考类别预测、条件概率、贝叶斯更新、决策树、情景分析、Monte Carlo、相关性和概率校准，因此值得建立严格 Skill。

### 7.2 触发条件

只有出现以下任务时触发：

- 要求数值概率或概率区间；
- 多个条件事件需要联合计算；
- 3 年、5 年等多期限事件需要一致处理；
- 不确定事件需要概率加权进入财务或估值；
- 使用 Monte Carlo、贝叶斯、决策树或随机分布；
- 需要比较基准、乐观、悲观情景并给权重。

普通的“分析可能性”“列出风险”“说明哪些证据会改变判断”不触发严格概率 Skill。

### 7.3 强制方法顺序

1. **先定义事件**：主体、产品、客户、地区、商业阶段、期限和成功阈值。
2. **优先使用阈值**：能回答“达到什么条件结论才成立”时，不强行给概率。
3. **再使用情景**：可用几种真实经营状态表达时，不强行构造概率分布。
4. **寻找参考类别**：只有筛选标准和可比性足够时才计算基础概率。
5. **更新公司特有证据**：说明证据为何提高或降低概率，不能按网页数量加点。
6. **处理依赖关系**：同源证据和共同产业条件不能当成独立事件相乘。
7. **最后才使用模拟**：只有输入分布和相关关系有依据时才使用 Monte Carlo。

### 7.4 竞争进入不另建 Skill

竞争进入研究中的以下内容并入本 Skill 的“事件和证据输入”：

```text
技术储备
→ 样品
→ 性能和可靠性验证
→ 客户测试
→ 正式认证
→ 小批量订单
→ 稳定量产
→ 重复订单和有意义收入
```

这条链只用于定义事件走到了哪一步，不需要单独注册 `competitive-entry` Skill。专利、招聘、联合演示和匿名产业链消息由现有来源质量与 claim 抽取规则处理。

### 7.5 数值概率最低门槛

必须同时具备：

- 清楚的事件合同；
- 可说明的参考类别或明确声明没有可靠基准；
- 事实证据与专家判断分离；
- 同源和依赖关系处理；
- 跨期限单调一致；
- 输入区间及其来源；
- 结果精度不超过输入精度；
- 可被新证据上调或下调的规则；
- 至少一种校准或外部合理性检查。

缺少这些条件时：

- 不输出精确概率；
- 改用低、中、高可能性；
- 或直接输出决定结论的阈值。

### 7.6 情景必须是经营状态

情景不能只是把所有变量统一增加或减少 10%。例如竞争进入可以分为：

- 未通过客户认证；
- 通过认证但只有有限订单；
- 稳定量产并获得中等份额；
- 进入头部客户并引发明显降价。

每个情景再把份额、ASP、毛利率、资本开支和时间路径传递给财务模型。概率 Skill 负责事件和权重，财务 Skill 负责利润与现金流，二者不得互相代替。

## 8. 不再建立 Skill 的内容怎样保留

### 8.1 模型路由

不建立 `opportunity-model-router` Skill。只在 ResearchBrief 或活动配置中保留一张简短触发表：

| 任务出现什么 | 调用什么 |
|---|---|
| 公司收入、利润、现金流预测 | 公司财务建模 |
| 目标价、价值区间、估值倍数 | 公司估值建模 |
| 市场规模、产能、供需、库存、量价 | 行业市场空间与供需建模 |
| 数值概率、联合事件、概率加权、随机模拟 | 概率与情景建模 |
| 只有证据综述、技术介绍或事件核验 | 不调用严格建模 Skill |

路由只是触发逻辑，不值得占用一个完整 Skill。

### 8.2 技术成熟度与替代

保留在行业研究 reference 中。若某行业存在明确标准，例如 TRL、MRL、AEC-Q、JEDEC 或特定客户认证流程，就按任务读取对应标准；不能用一套通用成熟度表覆盖所有行业。

### 8.3 监控与证伪

继续由 Opportunity Lens 的指标槽、补充研究和写作合同负责。只要求每个关键结论说明监控指标、来源、频率和证伪条件，不建立单独 Skill。

### 8.4 专利、招聘和弱信号

继续由 `source-quality-tier`、`claim-extraction-from-source` 和开放检索协议负责。可以增加简短 reference 解释专利家族、法律状态、岗位重复、客户认证等，但不注册新 Skill。

### 8.5 历史校准

不建立生产 Skill。它应是四个严格 Skill 共用的测试 harness，负责历史时点冻结、预测误差、情景覆盖率、概率校准和系统性偏差检查。

## 9. 四个 Skill 的共同内部合同

只保留真正影响复算的字段：

```text
input_name
value_or_range
unit
period_or_as_of_date
source
input_type
formula_or_method
output
sensitivity
limitations
```

`input_type` 统一区分：

- 直接事实；
- 根据事实推导；
- 外部预测或一致预期；
- 专家假设；
- 客观不可得。

每个 Skill 必须生成：

1. 模型选择和不适用方法；
2. 关键输入和来源；
3. 核心计算底稿；
4. 结果和必要的敏感性；
5. 独立复算结果；
6. 数据不足时的降级说明；
7. 可供正文使用的自然中文结论。

不再为每个逻辑步骤设计独立 manifest、矩阵或公开表格。

```text
   │  └─ scripts/

   │  ├─ SKILL.md

```

每个 `SKILL.md` 只保留触发条件、方法选择、最低数据要求、降级和输出合同。公式库、行业差异、数据字段和例子进入 `references/`；可重复计算和 sanity check 进入 `scripts/`。

## 11. 对现有 Opportunity Lens 任务的适用方式

| 任务 | 严格 Skill |
|---|---|
| 比亚迪、立讯进入光模块的概率和盈利影响 | 概率与情景 + 公司财务；若需要价值影响再加估值 |
| 硅片厂需求、产能与供需关系 | 行业市场空间与供需；涉及标的盈利再加公司财务 |
| 高多层 PCB 供需和市场空间 | 行业市场空间与供需；不需要单独“PCB Skill” |
| PCB 设备市场规模和公司订单兑现 | 行业市场空间与供需 + 公司财务；设备项目方法作为 reference |
| 单纯验证某项专利、招聘或客户传闻 | 不调用上述严格 Skill，走现有证据流程 |
| 单纯比较两条技术路线 | 不默认调用严格 Skill；只有计算市场、概率或财务时才触发相应 Skill |

## 12. 实施顺序

1. 先完成公司财务建模 Skill；
2. 再完成公司估值建模 Skill并与财务输出接线；
3. 建立行业市场空间与供需建模 Skill，先覆盖半导体、设备和 AI 硬件三个 reference；
4. 建立概率与情景建模 Skill，重点解决事件定义、参考类别、依赖关系和伪精确；
5. 用独立 fixture 回放既有专题计算，不修改历史 run；
6. 建立共用历史校准与数值复算 harness；
7. 验证后只把四个触发条件写入活动配置，不把整套 Skill 内容复制进 `AGENTS.md`。

## 13. 验收标准

每个严格 Skill 必须满足：

1. 有成熟专业方法或标准参照；
2. 触发和不触发条件明确；
3. 输入事实、推导、外部预测和专家假设分离；
4. 数据不足时能够降级，而不是补数；
5. 核心公式和结果能够独立复算；
6. 有数量级、单位、期间和会计或存量流量检查；
7. 输出精度不超过输入精度；
8. 至少有两个不同主题的测试样本；
9. 历史 run 只读回放，不自动改写；
10. Skill 本体保持精简，行业差异按需读取。

## 14. 最终判断

Opportunity Lens 不需要一套庞大的 Skill 树。真正值得像财务和估值一样严格约束的，是那些有成熟方法、需要选择模型、涉及实质计算、且 Agent 很容易自行拍数的问题。

因此最终只保留四个严格 Skill：

> 公司财务建模、公司估值建模、行业市场空间与供需建模、概率与情景建模。

其中 Opportunity Lens 相比既定财务估值体系真正新增的只有后两个。竞争进入、技术成熟度、公司敞口、监控、专利和招聘等内容不消失，但分别回归证据流程、行业 reference、财务模型输入或报告合同，不再各自扩张为顶层 Skill。
