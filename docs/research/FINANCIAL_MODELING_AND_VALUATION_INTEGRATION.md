# 财务估值建模与 Agent 整合设计

版本：`research.modeling_skills.v1`  
适用范围：A/B 行研、C 轨 Opportunity Lens、公司透视与 Viewer。

> **存储状态说明（阶段 1）**：本文中的四套 SQLite 与 `financial.db` 描述当前已实现的物理存储和历史兼容状态；财务域的语义、revision、reconciliation、model ledger 与研究治理仍是有效业务合同。四个 SQLite 文件不是长期 PostgreSQL 目标的物理数据库划分，迁移后的最终边界以 `openspec/changes/github-vm-dual-node-operations/` 的已批准方案为准。本阶段只建立安全 Git、依赖和 CI 边界，不修改财务数据、模型公式或任何 live 数据库。

## 1. 目标与边界

本次改造把公司财务、公司估值、行业供需、概率情景压缩为四个按需 Skill，并把结构化公司数据从普通研究事实中分离。它解决四类问题：独立利润预测不可复核、估值倍数缺少来源、事件概率直接跳到利润折扣、所有任务无条件加载长方法上下文。

系统不承诺每家公司都有完整产品模型或 DCF。模型复杂度服从数据质量；关键输入不可得时降级为财务桥、同行/历史区间、反向估值、阈值或条件情景，不补造单点。

2026-07-22 已对重新上传的 `PB-ROE估值体系和应用_0601.pptx` 完成 48 页逐页阅读、OOXML 正文/图表/批注抽取和方法差异审计。原实现正确保留了残余收益、历史/同行诊断和 PB-ROA 杠杆拆解，但历史 PB-ROE 映射误用了线性 PB，且缺少材料中的 Wilcox 对数理论关系和可持续增长/多阶段净资产滚动路径；这些偏差已经在模型、Skill、测试和公司页说明中纠正。完整审计见 `PB_ROE_PPTX_METHOD_AUDIT_20260722.md`。该材料标注为内部资料，其中关于短期指数预测效果的经验主张没有独立样本、完整回测口径和公开来源，因此没有被写成系统事实或自动交易规则。

## 2. 四库架构

| 数据库 | 权威内容 | 本次边界 |
|---|---|---|
| `research.db` | 行业、来源、研究事实、公司主体、动态和假说 | 保留公司身份和行业关系；不再新增供应商结构化财务数据点 |
| `sentiment.db` | 情绪、招聘、K 线和供应链镜像 | 不参与财务模型写入 |
| `opportunity_lens.db` | C 轨 run、证据、实体、评分、标的、报告和审查 | 只读引用公司身份与财务结果，不回写其他库 |
| `financial.db` | 证券、结构化公司数据、模型账本、修订和对账 | 公司财务与估值的新主路径 |

`financial.db` 主要对象：

- `financial_security` 与 `financial_security_company_link`：一个规范证券可以链接历史别名公司 ID，避免重复证券和观测；
- `financial_source_snapshot`：provider、原始字段、来源引用、截面日期和内容哈希；
- `financial_observation`：actual、market、consensus、guidance、internal_estimate、implied 六类事实；
- `financial_observation_revision`：同一观测身份发生供应商修订时保存前后值和原因；
- `financial_model_run/input/output`：完整输入、公式、代入、结果、角色、依赖簇和限制；
- `financial_reconciliation`：独立结果与一致预期、指引、市场隐含、同行或历史的差异。

观测唯一身份不包含运行时 legacy 引用，因此重跑不会把相同供应商观察复制成新事实。来源同时点冲突保留双方，不平均；同一来源的修订进入 revision。

## 3. 数据源与权限门禁

A 股使用项目 `WindPy.py` 的内网 HTTP 代理为主源，Tushare 只补 Wind 客观空缺，并提供逐机构预测、公告和重述审计；海外继续以 yfinance 为主。每字段保存真实 provider、raw feature、证券代码、期间、as-of、单位和公式。公司公告、交易所及监管披露仍是财务事实最终权威。

Wind 默认只允许小范围取数。单次超过 10 只证券、20 字段或预计 5,000 观测，或同一任务/北京时间自然日累计预计超过 50 只证券或 50,000 观测，必须先取得用户 permission；全市场、全 A 股长历史和分钟长历史天然属于大规模请求，不得拆单绕过。

## 4. 四个 Skill 与路由

| Skill | 性质 | 触发 | 强制产物 |
|---|---|---|---|
| `company_financial_modeling` | 硬方法 | 公司未来收入、利润、现金流、EPS、ROE、ROA；公司估值所需财务；事件对公司盈利影响 | FY1—FY3 独立冻结、输入输出账本、外部对账 |
| `company_valuation_modeling` | 硬方法 | 目标价、合理价值、高估/低估、PE/PB/DCF/反向估值 | 方法门禁、估值账本、反向估值、外部对账 |
| `industry_supply_demand_modeling` | 开放研究 | TAM、量价、渗透率、产能、有效供给、供需缺口 | 渠道隔离证据、公式/输入/结果、外部口径对账 |
| `probability_scenario_modeling` | 开放研究 | 竞争进入、技术替代、政策冲击、认证量产和事件概率 | 事件定义、证据与精度边界、事件到财务桥 |

`ResearchBrief` 的确定性路由只登记 Skill 路径、触发理由和强制产物，不复制全文。纯新闻、专利或招聘核验不加载建模 Skill；公司只预测利润时不因 ROE/ROA 是输出指标而误加载估值。新 run 使用 `research.modeling_skills.v1`：被路由 Skill 没有完成记录和输入/输出 SHA256，或公司模型缺少独立冻结/外部对账，发布门禁会阻塞。历史 pack 没有新标记时继续只读兼容，不补造执行事实。

## 5. 财务和估值合同

FY1—FY3 基础桥：

```text
收入 = 数量 × 价格，或历史收入 + 行业/新品/产能贡献 - 价格与份额压力
毛利润 = 收入 × 毛利率
归母净利润 = 毛利润 - 期间费用 - 净财务成本 - 税费 - 少数股东损益
EPS = 归母净利润 / 稀释后股数
ROE = 归母净利润 / 平均归母净资产
ROA = 归母净利润 / 平均总资产
```

先使用历史实际、公司正式披露和可核验行业输入形成独立模型并冻结哈希，之后才读取 Wind/Tushare 一致预期、公司指引和研报。对账差异不自动修改模型；只有发现新事实、单位/期间/口径错误或模型结构错误才变更，并保留修订原因。

估值门禁按正常盈利、周期、资产属性、杠杆、现金流质量、复合业务和行业特征决定。实现覆盖 Forward PE、目标倍数软调整桥、历史/同行倍数、EV/EBITDA、PS、反向 PE、DCF/FCFF、反向 DCF、Wilcox PB-ROE、可持续增长/多阶段 PB-ROE、PB-ROA、同行 PB、残余收益，以及条件式 SOTP、NAV、rNPV 和 DDM。SOTP 只有分部边界和独立利润/现金流充分时启用；NAV 必须逐项展示资产价值、折价和负债；rNPV 必须披露成功概率依据；DDM 只适用于资本约束和可分配股利路径能够解释的企业。DCF 只有未来 EBIT、税率、折旧、CAPEX、营运资本和 WACC/终值能解释并闭环时才可作为正式方法。

多个结果先按共同输入分为利润倍数、企业价值、资产回报和诊断模型簇，再解释集中或冲突；禁止把高度相关模型机械平均。

## 6. PB-ROE / PB-ROA

PB-ROE 不是单一公式。系统明确区分四条用途不同的路径：

1. Wilcox 理论路径，用预期可持续 ROE、股权资本成本、优势衰减期和终态 PB 解释当前 PB；
2. 可持续增长/多阶段路径，逐年预测净利润、分红和期末归母净资产，再折现股利与终值；
3. 残余收益路径，把超过股权资本成本的净资产收益折现回当前价值；
4. 历史与同行经验映射，只作诊断和交叉验证，不替代公司独立盈利预测。

Wilcox 路径为：

```text
ln(当前PB) = ln(终态PB) + (预期ROE - 股权资本成本) × 优势衰减年数
当前PB = 终态PB × exp[(预期ROE - 股权资本成本) × 优势衰减年数]
```

终态 PB 不强制等于 1。只有资产可变现质量、负债和减值风险均可解释时，PB 接近 1 才可能构成有条件的资产保护线，不能写成普遍安全底。

稳定增长路径必须先说明 ROE 时点。若 ROE 为当期利润/当期净资产口径，使用 PPT 的下一期股利口径：

```text
可持续增长率 = 预期ROE × (1 - 分红率)
合理PB = 预期ROE × 分红率 × (1 + 可持续增长率) / (股权资本成本 - 可持续增长率)
```

若输入已经是下一期利润/期初净资产的 forward ROE，则上式不再乘 `(1+可持续增长率)`。其前提是长期增长率低于股权资本成本；多阶段模型则必须逐年滚动“期末净资产＝期初净资产＋归母净利润－股利”。终值的下一年股利直接由预测期末净资产乘终端 ROE 和分红率得到，不能重复前推一轮增长，也不能把当前高 ROE 永续化。

残余收益路径为：

```text
股权价值 = 当前归母净资产 + 预测期残余收益现值 + 终值现值
残余收益_t = (ROE_t - 股权资本成本) × 期初归母净资产_t
```

历史关系每个财务报告期只配一个报告后 PB 截面，不能把年度 ROE 携带到每个交易日制造伪样本。至少三个独立报告期才拟合；默认拟合 `ln(PB)=a+b×ROE`，再把预测值还原为 PB，并展示样本数、系数、R²、对数残差描述带、当前点和 FY1—FY3 内部预测路径。历史实际 ROE 只是预期 ROE 的代理，不能把相关关系等同于目标 PB。

周期企业必须先判断周期位置，并预测价格、销量/产能、成本、利润和净资产，再计算跨周期可持续 ROE；位于周期高点但没有完成周期判断时，PB-ROE 门禁自动降级。PB-ROA 仍作为资产效率与杠杆诊断：高 ROE 但 ROA 一般、权益乘数高时，页面明确提示杠杆放大。公司页同时展示当前 PB/ROE/ROA、可得时的 ROIC、权益乘数、资产负债率、历史配对、预测路径、模型输入/公式/来源和限制；缺项显示“无直接数据”，不从相邻指标反推冒充。

## 7. 事件冲击和概率

事件概率与条件财务影响分开。概率回答“情景成为现实的可能性”；财务表回答“如果该情景已经发生，公司会怎样”。默认条件收入桥是：

```text
冲击后收入
= 基准收入
- 基准收入 × 可竞争业务占比 × [份额损失 + (1 - 份额损失) × 额外价格压力]
+ 可验证抵消收入
```

随后分别传导销量毛利、价格毛利、成本、费用、折旧/资本投入、税率、净利润、ROE/ROA和估值。缺乏校准基础时只输出低/中/高、宽区间或阈值，不用复杂模拟制造小数精度。除非明确计算“概率加权期望值”并解释用途，事件概率不得直接乘收入或利润。

## 8. 研报和网络搜索隔离

每个第一轮问题轴独立产生 report/web 两个任务。两条链路分别搜索、抽取、去重、评级和登记 `source_channel`，研报命中不能降低网络预算；分析时才合并并按 `independence_key` 识别共同底层来源。第二轮只处理第一轮发现的最新时点、冲突或关键假设 gap，必须保存 `gap_trigger`。

## 9. 公司身份与 Viewer

新增 `/companies`、`/api/companies/search`，支持中文名、英文名/别名和 ticker 搜索。Opportunity Lens 证券标的解析优先使用显式 `company_id`，否则只接受 ticker 或名称/别名的唯一精确匹配；歧义时拒绝装载，不自动猜母子公司或 A/H/ADR。

新的上市公司画像通过 `ensure_listed_company_profile.py` 显式核验创建；当前代码把 research 公司身份与 financial security 链接的更新组织在同一 SQLite `ATTACH` transaction scope 中，C 轨 loader 本身不越库写公司。该表述只说明应用的共同提交意图，不承诺 WAL 和主机崩溃条件下跨数据库文件具有无条件强原子性；PostgreSQL 迁移须把它作为共同业务事务边界审计。公司页显示六项核心指标、历史/FY1—FY3财务、内部预测与一致预期、多方法估值账本、PB-ROE/PB-ROA、市场隐含预期和相关 Opportunity Lens 链接。资产回报同行截面不能直接使用宽泛的 `company_industry` 成员：页面先限定同一核心行业、上市身份和同一产品层级，再保留财务库有 PB 或资产回报数据的公司，并明确这只是诊断样本。无法识别主营产品层级或通过门槛的公司不足两家时不生成伪同行表；正式同行估值仍必须另行说明业务可比性、增长、利润率、杠杆、风险和异常值处理。

## 10. 2026-07 财务 SQLite 改造的兼容与恢复记录

本节保留当时新增 `financial.db` 的历史实施合同，不是 GitHub—PostgreSQL—VM 迁移的当前目标架构，也不能推导出 PostgreSQL S3/S4 后可以恢复旧 SQLite。当前目标合同以 `openspec/changes/github-vm-dual-node-operations/` 为准。

迁移顺序是：外部安全副本和 `backup/latest` → 临时库迁移与 `foreign_key_check` → 代码/契约/页面回归 → live 迁移 → 四库完整性与只读页面验收 → 原子刷新 `backup/latest` → 受限清理项目外临时备份。

- research migration 只增加 `source_channel`，旧数据按可解释默认值兼容；
- Opportunity Lens migration 增加 search/source 渠道字段，不删除旧 run；
- financial migration 从 company 当前字段、profile 历史序列和旧结构化财务点建立新库，旧表不删除；
- Viewer 切换到财务库后，缺少新记录时显示明确空态，不回退拼接普通研究数据点；
- 当时在新 `financial.db` 尚未形成必须保留的新事实前，恢复迁移前三套原有 live 库与代码归档并移除新增库，是该次变更的受限撤回路径；这条历史记录不适用于未来 PostgreSQL 已产生有效新写入后的恢复。

## 11. 性能审计

`tools/research_core/modeling_benchmark.py` 比较“每次加载四个 Skill 正文”的 eager 代理与确定性路由。它明确不是补造的历史端到端实测，也不包含模型推理、网络、PDF或正文生成。2026-07-22 在最终 Skill 正文上的 100 次微基准显示：普通未来利润任务只加载一个 Skill，Skill 正文 bytes 减少 70.67%；普通估值加载两个，减少 41.54%；纯行业空间只加载供需 Skill，减少 77.29%；事实核验不加载建模 Skill；复杂竞争冲击仍加载四个，完整性不降级。详细结果见 `建模Skill按需加载性能审计_20260722.md`。
