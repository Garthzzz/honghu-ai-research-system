# 萝卜投研 Playwright 研报抓取：研究员与 Agent 使用手册

版本：`datayes_playwright` 研究员版  
适用范围：A/B 行研、Opportunity Lens 以及公司财务建模的卖方报告补充。

## 1. 这个功能是什么

Agent 使用 Playwright 操作萝卜投研 `https://r.datayes.com/` 的正常网页界面，完成标题检索、候选筛选、详情页查看和 PDF 下载。它不调用、逆向或绕过站点 API，不突破账号可见权限，也不自动处理验证码。

萝卜投研在系统中的角色是**卖方研报聚合入口**，不是独立证据发布方。下载到的报告必须按底层券商、报告标题和发布日期识别独立性。

这个功能主要解决三件事：

1. 用户没有预先提供足够研报时，Agent 能主动补充近期国内与外资研究；
2. 公司财务模型冻结后，Agent 能取得近期卖方预测用于外部对账；
3. 下载文件进入统一 `papers/` 库，并带有哈希、页数、券商、日期和检索过程，后续 A/B/C 轨可以复用。

萝卜投研只承担 `report` 研报链。Agent 仍必须独立执行 `web` 网络搜索链，查找公告、监管文件、公司/客户/供应商材料和产业原始数据；找到研报不能减少网络搜索预算。

## 2. 安全登录如何工作

账号和密码只通过本机遮罩窗口写入 Windows Credential Manager，后端必须是 `WinVaultKeyring`。密码不会经过聊天、命令行参数、环境变量、项目文件或日志。

首次配置：

```powershell
python -m tools.research_sources.datayes_reports configure-credentials
```

检查凭据是否已经配置：

```powershell
python -m tools.research_sources.datayes_reports credential-status
```

建立或刷新登录态：

```powershell
python -m tools.research_sources.datayes_reports login
```

脚本从系统凭据库取出账号密码，只向可见的登录表单填充并提交。若出现验证码、滑块或额外安全确认，需要用户在打开的浏览器里手工完成；Agent 不识别或绕过。登录墙连续消失后，浏览器自动关闭。

检查当前登录态：

```powershell
python -m tools.research_sources.datayes_reports status
```

登录态保存在本机浏览器 profile：

```text
tools/dynamic/secrets/datayes_profile_v2
```

该目录属于 secrets：不进入 Git、广播包、研究数据库或审计文件，不允许 Agent 读取、复制、总结或外发其中的 cookie、localStorage 和账号信息。

## 3. Agent 到底抓哪些研报

### 3.1 公司研究

| 维度 | 规则 |
|---|---|
| 标题关键词 | 公司全称或常用简称；必要时分开检索 A/H 股名称 |
| 时间范围 | 研究截止日前 183 天 |
| 页数 | 不设硬门槛，但优先有完整预测与估值的报告 |
| 目标组合 | 1—2 份外资卖方＋1—2 份国内推荐报告 |
| 核心用途 | 业务变化、FY1—FY3 预测、利润率、现金流、估值假设和市场分歧 |

公司财务建模中，卖方预测中位数只纳入研究截止日前最近两个季度发布的同公司报告。183 天是连接器的候选搜索上限；真正进入财务预测对账时还要执行“最近两个季度”筛选。更早报告只可用于理解历史业务、竞争格局或预期变化，不能混入当前预测中位数。

公司报告优先抓取：

- 最新年报/季报后的更新报告；
- 含收入、净利润、EPS、毛利率或自由现金流预测的报告；
- 能拆分业务量价、市场份额、资本开支或客户变化的报告；
- 明确解释目标 PE/PB/EV—EBITDA、DCF 或分部估值假设的报告；
- 与主流观点显著不同、能够解释预期差的报告；
- 外资报告中对海外客户、全球竞争和跨市场估值有增量信息的报告。

不优先抓取：只有评级结论、没有模型更新的快评；重复转载；同一券商同一报告的中英文或不同页面副本；与当前财务模型日期明显脱节的旧目标价。

### 3.2 行业研究

| 维度 | 规则 |
|---|---|
| 标题关键词 | 行业名、行业名＋深度、行业名＋行业深度 |
| 时间范围 | 研究截止日前 366 天 |
| 页数 | 实际 PDF 至少 20 页 |
| 目标组合 | 1—2 份外资卖方＋1—2 份国内推荐报告 |
| 核心用途 | 行业边界、供需、市场空间、竞争格局、技术路线、政策和产业链价值迁移 |

行业报告优先抓取：

- 行业深度、年度策略或中期策略；
- 给出市场规模、销量/产量、产能、价格、库存或渗透率时间序列的报告；
- 解释 CR3/CR5、国内外竞争格局和公司份额的报告；
- 有明确技术路线、BOM、价值量、成本曲线或产能投放节奏的报告；
- 讨论政策、贸易、地缘、资源安全和海外产业链的外资或多语言报告；
- 能把行业变量传导到公司收入、利润率和资本开支的报告。

不优先抓取日报、早报、晨报、单条新闻汇总、标题相关但正文只有少量行业内容的报告。行业 PDF 下载后必须再次检查实际页数，页面显示的页数不能代替文件验证。

## 4. 一次完整抓取怎样执行

### 第一步：把研究问题变成检索请求

一次请求至少包含：

- `query`：标题检索词；
- `papers-subdir`：`papers/` 下的目标行业目录；
- `scope`：`company` 或 `industry`；
- `as-of-date`：研究截止日；
- 国内推荐和外资目标数：各 1 或 2。

公司示例：

```powershell
python -m tools.research_sources.datayes_reports search `
  --query "正泰电器" `
  --papers-subdir "光伏" `
  --scope company `
  --as-of-date 2026-08-01 `
  --domestic-target 2 `
  --foreign-target 2
```

行业示例：

```powershell
python -m tools.research_sources.datayes_reports search `
  --query "碳酸锂 深度" `
  --papers-subdir "碳酸锂" `
  --scope industry `
  --as-of-date 2026-08-01 `
  --domestic-target 2 `
  --foreign-target 2
```

`papers-subdir` 只能是 `papers/` 下的安全相对目录，不能用绝对路径或 `..` 越界。

### 第二步：Playwright 在网页上做什么

1. 使用持久化 profile 打开萝卜投研首页并确认登录态；
2. 进入研报搜索页面；
3. 强制选择“标题”检索，找不到标题模式则停止；
4. 输入关键词并回车；
5. 分别收集主搜索结果、“推荐”标签和“外资研报”标签；
6. 打开最多四个高相关详情页，从详情页的相关/推荐报告继续发现候选；
7. 按底层券商＋标题＋发布日期去重；
8. 根据日期、标题相关性、页数和国内/外资类别筛选；
9. 生成脱敏的候选与配额审计。

行业查询包含“深度”时，连接器会同时尝试去掉“深度”的较宽关键词，避免因为标题措辞不同漏掉相关报告。宽搜索仍须通过标题相关性、日期和页数门槛。

### 第三步：候选如何选择

候选先按发布日期从新到旧排列，再分为：

- 外资卖方报告；
- 萝卜投研“推荐”标签中的国内报告；
- 普通标题检索命中的国内报告。

系统优先选择外资和国内推荐报告。若“推荐”标签没有足够相关国内报告，可用标题检索命中的近期国内深度报告作为参考回退，但必须标记为 `search_result`。这个回退可以被下载和使用，却**不能冒充平台推荐，也不能使严格推荐配额变成通过**。

多篇报告来自同一底层报告、转载、翻译或聚合副本时只算一个证据组。萝卜投研本身不增加独立性。

### 第四步：先看候选，再下载

`search` 只生成候选审计，不下载 PDF，适合先检查关键词和配额。确认范围后使用：

```powershell
python -m tools.research_sources.datayes_reports download `
  --query "碳酸锂 深度" `
  --papers-subdir "碳酸锂" `
  --scope industry `
  --as-of-date 2026-08-01 `
  --domestic-target 2 `
  --foreign-target 2
```

Agent 进入每个选中报告详情页，只点击正常网页中可见的“下载/PDF下载”控件，并由 Playwright 接收浏览器下载事件。找不到可见下载控件时记录失败，不改用逆向接口。

### 第五步：下载后怎样验证

文件先进入：

```text
cache/datayes_reports/downloads/<批次>/
```

随后依次检查：

1. 文件存在且不为空；
2. 文件头为 `%PDF-`；
3. PyMuPDF 可以打开；
4. 行业报告实际页数不少于 20；
5. 计算 SHA256；
6. 生成 Windows 安全文件名；
7. 原子移动到 `papers/<行业>/`。

文件名经过统一规范化，最长文件名和项目相对路径受 Windows 广播部署限制。若同名文件哈希一致则复用，不重复保存；同名但内容不同会追加稳定哈希消除冲突。

## 5. 抓取完成后会产生什么

### PDF

```text
papers/<行业>/<发布日期>_<券商>_<报告标题>.pdf
```

### 来源清单

```text
papers/<行业>/_source_manifests/datayes_<scope>_<token>.json
```

清单记录：

- PDF 相对路径、SHA256、字节数和实际页数；
- 报告标题、底层券商和发布日期；
- 萝卜投研详情页；
- 公司/行业范围、搜索词和标题检索模式；
- 国内/外资分类以及推荐、外资或普通搜索结果身份；
- `independence_key` 和独立性说明；
- 下载失败项和错误类型；
- 实际配额是否满足。

清单不包含账号、密码、cookie 或浏览器存储。

### 审计 cache

```text
cache/datayes_reports/search_<token>.json
cache/datayes_reports/download_<token>.json
```

这些文件用于检查搜索范围、候选数量、配额和失败原因，不等于研究证据本身。

## 6. 报告怎样进入 A/B 行研

1. 每个问题轴仍独立生成 `report` 和 `web` 两条搜索任务；
2. 萝卜投研下载报告后，PDF 逐页建立文本和哈希索引；
3. Agent 从 PDF 抽取本轮实际使用的原文、页码和数据；
4. 统一 ingest 根据 `_source_manifests` 补齐券商、发布日期、详情页、来源层级和 `source_channel=report`；
5. 只有真正支持数据点或核心论点的报告才进入 `research.db.source`；
6. 只是下载备用、正文没有引用的报告不会自动制造研究事实。

研报里的数据仍需检查单位、期间、原始出处和方法。卖方自行估计的数字应标为预测或推断，不能包装成公司已披露事实。

## 7. 报告怎样进入 Opportunity Lens

1. `_source_manifests` 作为来源生产阶段的 provenance seed；
2. Agent 从 PDF 提取本轮实际使用的原文，并为英文原文写中文译意；
3. 转换时重新核对 PDF SHA256，文件变化则拒绝沿用；
4. 新来源先处于待 evidence reviewer 审查状态；
5. 独立性按底层券商＋标题＋发布日期计算，不按萝卜投研页面数量计算；
6. 卖方研报属于二手研究证据，不能替代公告、监管披露、专利、公司/客户/供应商和政府资料；
7. 公司 FY1—FY3 卖方预测只在独立模型冻结后用于外部对账。

英文报告和同类型中文报告采用相同的质量标准，不因语言或翻译成本降权；但公开输出必须提供准确的中文标题和本轮使用原文的中文译意。

## 8. 研究员怎样判断“抓够了”

最低配额只是起点，不是停止搜索的充分条件。尤其是新行业、全球竞争、海外客户或可能改变利润预测的主张，还需要检查：

- 是否至少有一至两份近期外资报告；
- 是否至少有一至两份近期国内推荐或明确标注的标题回退报告；
- 是否覆盖最新年报/季报后的预测更新；
- 行业报告是否覆盖供需、竞争、技术、政策和公司传导，而非只讲市场空间；
- 关键数字是否能追溯到公告、监管或公司原始披露；
- 多篇研报是否其实引用同一个底层来源；
- 是否主动搜索反方、降价、替代路线、需求放缓和财务兑现风险；
- 新增报告是否仍带来新的数据、方法或冲突解释。

当关键问题已经覆盖、重要数字已溯源、反方已搜索且继续增加报告的边际信息明显下降时，才可以停止。配额满足不能替代研究判断。

## 9. 常见失败和处理方式

| 问题 | 正确处理 |
|---|---|
| 登录失效 | 重新运行 `login`，不手工复制 cookie |
| 验证码或安全确认 | 用户在可见浏览器完成，Agent 不绕过 |
| 页面改版、找不到搜索框或标题选项 | 运行 `probe-ui` 生成脱敏结构后修选择器 |
| 找不到下载按钮 | 记录详情页 path 和错误类型，不逆向 API |
| 券商或日期无法核验 | 候选不进入正式配额 |
| 外资或国内推荐不足 | 保存已成功报告并返回 `shortfall`，不造数 |
| 国内仅有普通标题结果 | 可作回退参考，但不能标成“推荐” |
| PDF 损坏或行业报告少于20页 | 拒绝入库并记录失败 |
| 标题太长或 Windows 路径不安全 | 使用统一路径规范化，不手工改已被引用文件 |

页面改版诊断命令：

```powershell
python -m tools.research_sources.datayes_reports probe-ui
```

`probe-ui` 只记录脱敏后的输入框、按钮和站内路径结构，不保存输入值、cookie 或完整页面正文。

## 10. 返回状态如何理解

- `complete`：严格国内推荐和外资配额均满足，且下载没有失败；
- `shortfall`：配额不足、只有回退材料或某些下载失败；真实成功项仍会保留；
- 登录相关命令失败：先处理凭据、登录态或用户安全验证；
- UI 结构失败：先 probe，不反复盲点页面；
- PDF 验证失败：文件不进入 `papers/` 正式库。

`shortfall` 不等于“没有信息”，但研究正文必须说明实际取得多少报告、缺少哪类材料及其对结论置信度的影响。

## 11. 使用纪律

- 只按具体研究请求运行，不配置无目标的高频定时下载；
- 优先 `search` 审核候选，再 `download`；
- 不把下载数量当研究深度；
- 不把卖方结论当一手事实；
- 不因英文原文降低证据权重；
- 不把同一底层报告的多种页面或翻译当独立来源；
- 不把旧公司目标价混入当前两个季度的财务预测对账；
- 不把凭据、profile 或登录态放入 Git、广播包、cache 审计或研究产物；
- `papers/` 的新增文件必须保留来源清单和安全路径。

## 12. 一套推荐的实际操作顺序

```text
明确研究问题与截止日
→ 检查登录态
→ 分别设计公司/行业标题关键词
→ 先 search 看候选、时间和国内/外资配额
→ 调整过宽或过窄关键词
→ download 下载选中报告
→ 检查 PDF、页数、哈希和来源清单
→ report 链逐页抽取
→ web 链独立搜索原始证据和反方
→ 去重、评级和溯源
→ 财务模型先独立冻结
→ 用最近两个季度公司报告做外部对账
→ 写入 A/B 或 C 轨正式产物
```
