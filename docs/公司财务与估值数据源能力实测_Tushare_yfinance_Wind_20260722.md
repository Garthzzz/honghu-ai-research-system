# 公司财务与估值数据源能力实测：Tushare、yfinance、Wind 与 Ricequant

更新时间：2026-07-22（北京时间）  
测试对象：A 股消费、成长制造、银行、资源、公用事业和亏损生物医药六类样本；美股 Apple、Microsoft、NVIDIA、Amazon 和 JPMorgan 五类样本  
任务边界：接口能力研究和样本请求均为只读，未写入 `research.db`、`sentiment.db` 或 `opportunity_lens.db`。用户随后明确长期授权项目使用内网 Wind HTTP 代理，项目策略已调整为“A 股 Wind 主源、Tushare 逐字段补缺和审计补充，其他市场 yfinance 主源”；本报告同步该最新结论。Ricequant 部分区分“米筐官方 RQData 产品能力”和“`honghu_ricequant_skill.md` 指向的公司内网 ClickHouse 能力”，二者不能混为一谈。

所有当前可取得的原始字段、来源、市场、历史/未来长度、频率、与估值/盈利/三表建模的关系及本课题有用性，已经统一整理到[《公司财务建模可用字段总目录》](公司财务建模可用字段总目录_20260722.md)。目录逐行保留原始 `feature_name`，并区分官方字段、当前账号实测和只读元数据，不能只看接口存在就认为每家公司都有值。

## 一、结论先行

1. **A 股标准化财务、当前估值和一致预期以 Wind 为主更合理，Tushare 不应被描述成比 Wind 更权威的主源。** 六类 A 股样本显示 Wind 当前估值、历史三表、现金流、CAPEX、研发和未来三年核心预测覆盖强；Tushare 真正不可替代的增量是原始三表字段、公告/重述标记和逐券商逐报告 `report_rc` 明细，适合补缺、复算一致预期和审计，而不是与 Wind 全字段重复平均。

2. **美股历史财务和近端一致预期，yfinance 是当前实际可用的主源。** Apple 实测取得五个年度、五至六个季度以及一个 TTM 时点的利润表、资产负债表和现金流量表，并取得当前年/下一年、当前季/下一季的收入与 EPS 一致预期、分析师人数、高低区间、EPS 预测修正、目标价和评级分布。它的缺点是历史窗口较短，未来只到下一财年，且字段是否返回高度依赖证券和市场。

3. **yfinance 对 A 股“能用但不完整”。** 贵州茅台实测可以取得当前 PE、forward PE、PB、PS、EV/EBITDA、ROE、ROA、EPS、BPS、四年年度报表及近五至六个季度报表；收入一致预期也有返回。但结构化 EPS 一致预期、EPS 修正、完整目标价和评级为空。它只作为 Wind 与 Tushare 均不可用时的应急来源，不进入 A 股常规双源组合。

4. **Tushare 文档层面已经提供美股四张财务接口，但当前账户没有权限。** `us_income`、`us_balancesheet`、`us_cashflow` 和 `us_fina_indicator` 四项实测均返回无访问权限。因此“平台有接口”不等于“本项目现在能用”；在权限未升级前，不能把 Tushare 计入美股可用数据源。

5. **米筐内网两张分析师表现在已经开通权限，但它们不是完整的一致预期财务表。** `stock_analyst_consensus` 实测覆盖 2016 年以来约 5165 只证券，144 个数值字段全部围绕 ROE、ROA及其增长，按不同预测序号和 5—180 日窗口展开；`stock_analyst_adjustment` 覆盖约 4848 只证券，提供 12 个不同预测序号和 31—181 日窗口的调整特征。它们适合做盈利质量预期和分析师调整动量，但没有收入、净利润、EPS、BPS、现金流、PE/PB 等绝对预测，不能替代 Tushare 或 Wind 的盈利预测。

6. **米筐官方 RQData 产品的潜在预测字段比当前内网视图丰富得多，但尚未接入当前生产链路。** 官方因子清单共 519 项，包含未来一至三年和未来 12 个月的净利润、EPS、收入、营业成本、营业利润、经营现金流、净资产、ROE，以及 PE/PB/PS/PCF、预测修正和市场信心。当前内网只有 ROE/ROA 与调整特征，没有把这些绝对预测映射进来；因此必须把“官方产品可提供”与“内网现在能读取”分开描述。

7. **Wind 项目根目录的 `WindPy.py` 代理在 A 股上的覆盖比先前判断完整得多。** 定向绕过本机 VPN 代理后，六类 A 股样本均可取得当前估值、历史报表和未来三年收入、净利润、EPS、平均 ROE；历史端还实测取得经营现金流、CAPEX、研发、主要资产负债表科目、FCFF/FCFE、ROIC、周转率和 EV/现金流估值。未来 BPS/PB、ROA、CFO、CAPEX、EBITDA 等猜测字段仍未通过当前代理字段映射验证。正式 Wind SDK 因试用版限制不再作为本任务问题，也不影响根目录代理取数。

8. **Wind 的美股缺口是系统性的，不能用它替代 yfinance。** Apple、Microsoft、NVIDIA、Amazon 和 JPMorgan 五只样本中，收入、净利润、利润率、ROE/ROA、EBIT/EBITDA和部分估值可以返回，但原始经营现金流、CAPEX、研发、PB/BPS、总资产/总负债以及 12 个 `west_*` 三年预测字段普遍为空。部分 EV、EV/EBITDA、P/OCF、ROIC 和周转率等衍生值可用，但不足以闭合美股三表。

9. **没有一个当前链路能够独立支撑所有市场、所有公司类型和所有预测期限。** 最稳妥的组合是：A 股以 Wind 为字段主值，Wind 客观缺失时才用 Tushare 补齐；Tushare另行保留逐机构预测和公告/重述审计，米筐补充 ROE/ROA 与调整动量；美股以 yfinance 为主；三年以上和行业经营变量由内部模型生成。两源同口径冲突时保留双方观测并核查，不做算术平均。

## 二、一个可靠公司金融模型到底需要什么数据

估值偏离市场，往往不是因为少了一个 PE 或利润数字，而是因为实际值、预测值、时点、币种、股本和估值桥没有统一。下面是建立通用公司金融建模体系时应保留的完整数据层。

### 2.1 证券身份、会计日历和时点

这是所有后续计算的主键，不能省略。

| 数据组 | 核心字段 | 为什么必须有 |
|---|---|---|
| 证券身份 | 发行人、证券代码、交易所、股份类别、ADR 比例、上市状态 | 防止把母公司、子公司、A/H 股或 ADR 混在一起 |
| 会计日历 | 财年结束日、报告期开始/结束日、季度类型 | Apple 的财年不是自然年；FY1 不能机械等于“明年” |
| 信息时点 | 公告日、实际公告日、估计发布日期、行情时间、抓取时间 | 避免使用当时尚未公开的数据，支持 point-in-time 回测 |
| 会计口径 | GAAP/IFRS/中国准则、合并/母公司、累计/单季、原始/重述 | A 股季度报表通常是年内累计，直接当单季会严重高估 |
| 单位与币种 | 原币、原始单位、换算汇率及日期 | 万元、元、百万美元、亿美元只改标签不换数值会造成百倍错误 |

### 2.2 市场价格、股本和估值桥

- 当前价、前收盘、复权价、成交量、行情时间。
- 总股本、流通股、自由流通股、基本加权股数、稀释加权股数、期权/限制性股票和潜在稀释。
- 总市值、流通市值、企业价值；净债务、租赁负债、优先股、少数股东权益、养老金缺口、非经营性现金和长期投资。
- 当前和历史 PE、PB、PS、P/OCF、P/FCF、EV/Sales、EV/EBITDA、EV/EBIT、PEG、股息率和 FCF 收益率。
- 当前估值和预测估值必须分开：PE-TTM、PE-FY0、PE-FY1、PE-FY2 的分母不同，不能共用一个“PE”标签。

### 2.3 利润表

- 营业收入及产品、地区、客户、订阅/硬件等分部收入。
- 销售成本、毛利、毛利率。
- 销售费用、管理费用、研发费用、股份支付、重组费用和其他一次性项目。
- EBIT、EBITDA、折旧摊销、净利息、税前利润、所得税和实际税率。
- 净利润、归母净利润、扣非净利润、调整后净利润。
- 基本/稀释 EPS，基本/稀释加权股数。
- 收入、毛利、营业利润、净利润和 EPS 的同比、环比、TTM 与多年 CAGR。

### 2.4 资产负债表和营运资本

- 现金、短期投资、应收账款、合同资产、存货、预付款、其他流动资产。
- 应付账款、合同负债/递延收入、应付薪酬、其他流动负债。
- 固定资产原值/净值、在建工程、使用权资产、商誉、无形资产、递延所得税。
- 短期债务、长期债务、租赁负债、优先股、少数股东权益和普通股权益。
- 应收、存货、应付周转率及周转天数，现金转换周期。
- 净营运资本及收入占比，用于把收入增长传导到现金流。

### 2.5 现金流、资本开支和资本配置

- 经营现金流、营运资本变动、折旧摊销、股份支付。
- 资本开支；最好同时保存现金流量表 CAPEX 和固定资产/在建工程变化，识别口径差异。
- 自由现金流：`FCFF = EBIT × (1－税率) + 折旧摊销－资本开支－营运资本增加`。
- 股东自由现金流、并购/资产处置、投资支出、债务发行/偿还。
- 分红、回购、增发及净股本变化。
- CAPEX/收入、研发/收入、并购/收入和再投资率。

### 2.6 盈利质量、回报和风险

- 毛利率、营业利润率、EBITDA 利润率、净利率、FCF 利润率。
- ROE、ROA、ROIC、投入资本周转率；需要明确平均余额、期末余额、年度化还是 TTM。
- 经营现金流/净利润、自由现金流/净利润、应计利润、一次性损益占比。
- 流动比率、速动比率、净债务/EBITDA、利息保障倍数、债务期限和固定/浮动利率结构。
- 客户集中度、供应商集中度、订单/在手合同、质保或诉讼准备等标准报表外风险。

### 2.7 未来预期和预测变化

最低应覆盖当前季度、下一季度、当前财年、未来一至三财年：

- 收入、毛利、毛利率、EBIT、EBITDA、净利润、EPS、DPS。
- 经营现金流、资本开支、自由现金流、净债务。
- ROE、ROA、ROIC、BPS，以及由同一估计快照和同一股价计算的 forward PE/PB/EV/EBITDA。
- 平均值、中位数、高低值、分析师数量、预测离散度。
- 7/30/60/90 天预测上修与下修、盈利惊喜、目标价与评级变化。
- 管理层指引和卖方一致预期必须分层保存，不能混成一个“未来利润”。

### 2.8 行业经营驱动

通用财务表只能解释结果，不能替代经营预测。不同产业至少还需要：销量、ASP、产能、利用率、良率、单位成本、订单、积压订单、客户认证、门店/用户、ARPU、云资本开支等。行业驱动用于预测收入和利润率，三张报表用于约束现金、资本和资产负债表闭环。

### 2.9 各类数据的自然频率

| 数据类型 | 正确频率 | 不应怎样处理 |
|---|---|---|
| 股价、PE/PB/PS、市值 | 交易日或盘中快照 | 不应把月末抽样写成“月度财务数据” |
| 利润表、现金流量表 | 季度、半年度、年度；可派生 TTM | 没有真实月度利润；不能把季度数机械均分到三个月 |
| 资产负债表 | 季末/年末时点 | 不能像收入一样相加 |
| ROE、ROA、周转率 | 随财报更新，季度/年度/TTM | 必须注明是否年度化和平均余额口径 |
| 卖方预测 | 报告发布时不定期变化；适合保存每日截面 | 不是固定月频；月度值只能是“月末可见的最新预测” |
| 管理层指引、业绩预告 | 事件驱动 | 没披露的月份不能补零或补估计 |
| 内部模型 | 每次新财报、指引或关键经营假设变化时重算 | 更新频率不等于数据事实频率 |

因此，标准模型可以生成月度估值监控，但历史财务事实仍应保持季度/年度口径；月度层只保存当月行情和当时可见的最新预测截面。

## 三、项目当前接线比供应商能力窄多少

本次实测的是“供应商能返回什么”，不等于项目已经把这些字段全部接入生产。当前代码边界如下：

- `tools/pipeline/tushare_provider.py` 已接入 A 股 `daily_basic`、利润表、资产负债表、现金流、财务指标、公司档案和披露日历。
- `tools/pipeline/market_snapshot_utils.py` 能整理 PE-TTM、forward PE、PB、PS-TTM、EV/EBITDA、PEG、市值、ROE、ROA、EPS-TTM、BPS、经营现金流、CAPEX、毛利率、净利率和研发占比。
- `tools/pipeline/company_financial_series_utils.py` 能取得年度/季度收入、利润、研发、经营现金流、CAPEX及部分资产负债表科目。
- 当前统一公司刷新只把 PE-TTM、forward PE、PB、PS-TTM、EV/EBITDA、PEG、市值、ROE、ROA、EPS-TTM 和 BPS-MRQ 纳入标准数值字段；供应商能返回的完整三表和预测数据没有全部进入同一持久化合同。
- 项目尚未发现通用的 Tushare `report_rc` 一致预期适配器。Opportunity Lens 有一个 BYD/立讯专题脚本调用过 yfinance 的收入/EPS 预测接口，但它是专题采集代码，不是可复用的全公司预测层。
- 现行 `tools/pipeline/data_source_policy.py` 允许 `api_wind`、`api_tushare` 与 `api_yfinance`。统一公司刷新已经接入 A 股 Wind 内网 HTTP 主快照和 Tushare 逐字段补缺，并在 manifest/数据点保留每个字段的实际 provider；Ricequant 目前仍不在生产允许列表。

这意味着下一步不能只扩充前端字段。应先建立独立的历史报表层和预测截面层，再让估值模型引用；否则把大量未来数据直接塞进 `company` 当前快照，会丢失预测日期、目标财年、机构数和分布。

## 四、本次怎么测试

### 4.1 测试原则

- 先读官方接口文档和项目实际代码，再调用接口。
- 只选一只 A 股和一只美股，不做全市场扫描。
- 所有请求只读，不写业务数据库，不生成回填 manifest。
- Tushare 和 yfinance 使用代表性短窗口；Wind 在用户追加授权后改为多次单证券小请求，逐项拆分字段，但不做全市场、多证券批量、分钟长历史或大表导出；Ricequant 只读官方文档和内网元数据/小样本。
- “文档声明”“账户有权限”“样本返回非空”分别记录，不互相替代。
- 实测值只用于验证字段和频率，不作为投资结论。

### 4.2 请求账本

| 数据源 | 实际动作 | 请求规模 | 结果 |
|---|---|---:|---|
| Tushare | 600519.SH 的 daily_basic、三张报表、fina_indicator、report_rc、forecast、express；AAPL 的四项美股财务接口 | 13 次单证券请求 | A 股除 express 外均有结果；美股四项均因账户无权限失败 |
| yfinance 1.2.0 | 600519.SS、AAPL 的 info、年度/季度/TTM 报表和分析师接口 | 两只证券，小样本 | 两个市场历史报表均成功；美股预测完整度明显高于 A 股 |
| 项目根目录 `WindPy.py` 代理 | 先做默认代理/直连对照；再以六只 A 股和五只美股分拆 WSS/WSD 字段，验证历史财务、当前估值和预测 | 单证券、小字段组请求；无全市场扫描、分钟长历史或批量导出 | 定向绕过本机 VPN 后主备地址均成功；A 股实际值和近三年预测覆盖强，美股原始报表与预测存在系统缺口 |
| Ricequant 官方 RQData | 阅读当前 Python/HTTP API、A 股财务、一致预期与更新履历文档 | 未调用官方数据接口 | 当前环境未安装 `rqdatac`，也没有使用或查找官方账户凭证，故只记录文档能力 |
| 公司内网 Ricequant ClickHouse | 表清单、建表定义、相关表结构/覆盖率、代表性单证券与横截面小样本 | 只读元数据和受限聚合/单证券查询 | 行情、估值、Tushare 派生财务指标及两张分析师表均可读；分析师表仅含 ROE/ROA 与调整特征；无美股数据 |

关于 Wind 额度：本轮为了区分字段错误、空值和链路错误，进行了多次单字段或小字段组探针，并补充了六只 A 股、五只美股的窄字段横截面；没有全市场、证券列表、分钟长历史或批量财务下载。本地代理没有暴露服务端计费统计，因此本文不声称精确计费单元数。用户已确认正式 Wind SDK 受试用版限制，本轮后续不再测试正式 SDK，所有 Wind 结论均指项目根目录 `WindPy.py` 代理。

## 五、Tushare：文档能力与账户实测

Tushare 的 A 股基础估值、报表与财务指标文档较完整，官方权限表也将这些接口标为历史全量、随财报或交易日更新。主要文档包括[每日指标](https://tushare.pro/document/2?doc_id=32)、[利润表](https://tushare.pro/document/2?doc_id=33)、[资产负债表](https://tushare.pro/document/2?doc_id=36)、[现金流量表](https://tushare.pro/document/2?doc_id=44)、[财务指标](https://tushare.pro/document/2?doc_id=79)、[业绩预告](https://tushare.pro/document/2?doc_id=45)和[券商盈利预测](https://tushare.pro/document/2?doc_id=292)。

### 5.1 A 股当前估值和行情

`daily_basic` 是交易日频率，实测 2026-07-01 至 2026-07-21 返回 15 个交易日。可直接取得：

- 收盘价、PE、PE-TTM、PB、PS、PS-TTM、股息率。
- 总股本、流通股本、自由流通股本。
- 总市值和流通市值。

600519.SH 在 2026-07-21 的样本值为：收盘价 1,308 元、PE-TTM 19.77 倍、PB 6.04 倍、PS-TTM 9.50 倍。该数值只用于证明接口返回，不能和不同时间的 yfinance 快照直接比较。

### 5.2 A 股历史财务

| 接口 | 本次返回 | 主要可用字段 | 频率和口径 |
|---|---:|---|---|
| `income` | 28 行 | 收入、营业利润、利润总额、净利润、归母净利润、基本/稀释 EPS、EBIT、EBITDA、研发费用 | 季报/中报/三季报/年报；一般为年内累计，需按 report_type 和 update_flag 去重 |
| `balancesheet` | 28 行 | 现金、应收、存货、固定资产、在建工程、总资产、总负债、归母权益、股本 | 季度时点值 |

本次主动限制在 2021-01-01 以后，已经覆盖五年以上。官方文档称三张报表为全部历史；`fina_indicator` 单只股票每次最多 100 条，超长历史需要按日期分段，但没有必要在日常刷新时反复全量拉取。

几个必须注意的口径：

- `cashflow.c_pay_acq_const_fiolta` 是购建固定资产、无形资产和其他长期资产支付的现金，可作为 CAPEX 主代理，但不等于会计附注中的全部资本性投入。
- `cashflow.free_cashflow` 是供应商给出的字段；项目自建 FCFF 时仍应保留公式和底层输入，不能与供应商 FCF 混用。
- 一季度 ROE/ROA 可能是累计期或年度化口径，必须使用字段定义，不得和年度 ROE 直接横比。
- 资产负债表是期末存量，利润和现金流是期间流量；ROE/ROA 自行复算时应优先使用平均权益/平均资产。

### 5.3 A 股未来数据

#### 券商盈利预测 `report_rc`

这是目前最有价值的 A 股未来数据入口。2026-07-06 至 2026-07-20 的贵州茅台样本共 55 行、19 家机构，覆盖：

| 预测财年 | 记录数 | 可直接取得的主要字段 |
|---|---:|---|
| 2026Q4 | 19 | 收入、营业利润、利润总额、净利润、EPS、PE、股息率、ROE、EV/EBITDA、评级 |
| 2027Q4 | 19 | 同上 |
| 2028Q4 | 17 | 同上，部分字段缺失更多 |

这里的每一行是某家券商某篇报告的预测，不是 Tushare 已经整理好的 consensus。正确处理方法是：

1. 同一机构、同一目标财年只保留估计日最新的一条；
2. 明确估计截面日，例如“2026-07-22 可见的最新预测”；
3. 分别计算中位数、均值、高低值、机构数和离散度；
4. 剔除过期、目标财年错位和单位异常记录；
5. PE 必须用同一报告中的 EPS/股价口径，或用统一估值日股价重新计算；
6. 不能把报告数量当独立信息数量，同一机构多篇报告只算一套最新观点。

实测字段覆盖并不整齐：55 行均有净利润和 EPS，50 行有 PE，47 行有 ROE，38 行有收入和 EV/EBITDA；目标价字段明显不完整。`report_rc` 没有标准的 forward PB、ROA、资本开支、经营现金流或自由现金流预测，这些仍要由三表模型推导。

#### 业绩预告与业绩快报

- `forecast` 是公司披露的区间预告，实测取得 2024 年归母净利润及同比区间。它是事件驱动、不定期更新，只覆盖公司主动预告的报告期，不是多年度一致预期。
- `express` 是业绩快报，贵州茅台在本次 2025 年以后窗口返回空表。接口存在不等于每家公司每期都有快报。
- 财报披露计划可以提供预计披露日期，但不是利润预测。

| 证券 | PE-TTM | forward PE | PB | ROE | ROA | 字段完整性判断 |

#### 美股 AAPL

## 七、Wind：根目录代理的实测能力、VPN 根因与字段边界

Wind 官方对 [Client API](https://www.wind.com.cn/mobile/ClientApi/en.html) 的描述包括全球上市公司基本面、财务表现和盈利预测；本轮代理实测确认账户至少能取得其中一部分 A 股和美股数据。公开网页没有给出本账户适用的完整指标代码字典，字段选择仍应以 Wind 终端代码生成器为准，不能靠相似字段名猜测。

### 7.1 本轮只评价项目根目录 `WindPy.py`

用户已确认正式 Wind SDK 受试用版限制，因此正式客户端不再是本任务的候选链路，也无需继续诊断。本文以下所有“Wind 实测”都指项目根目录 `WindPy.py`：它把 `wss`、`wsd` 等请求发往两台内网服务，不依赖本机 Wind DLL。这个代理返回什么，才是当前项目真正可用的 Wind 能力。

### 7.2 先前 502 的真正原因是本机 VPN 代理

当前 PowerShell/Python 进程同时存在：

```text
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
NO_PROXY=localhost,127.0.0.1
```

两个 Wind 内网地址使用的是 `http://`，所以直接影响它们的是 `HTTP_PROXY`，不只是 `HTTPS_PROXY`。对同一个 `600519.SH + sec_name` 请求做完全相同的编码后，结果如下：

| 请求路径 | 主地址 | 备地址 | 返回内容 |
|---|---:|---:|---|
| 保留默认代理环境 | HTTP 502 | HTTP 502 | 空响应 |
| 仅对 Wind 内网地址禁用代理 | HTTP 200 | HTTP 200 | 两端都返回“贵州茅台” |

因此，502 来自本机 VPN/代理路径，不是两个 Wind 内网服务共同宕机。测试中没有关闭用户的全局 VPN，只给单次子进程设置：

```powershell
$env:NO_PROXY='localhost,127.0.0.1,10.5.5.230,10.5.1.230'
```

### 7.4 未来预测到底有哪些，哪些仍没有验证

当前可直接、稳定取得的绝对预测是未来三年收入、净利润、EPS 和平均 ROE；还验证了收入/净利润的 CAGR、同比，以及 FY1 收入、净利润和 EPS 在 1、3、6 个月前的历史预测值。它们足以完成盈利一致预期、盈利修正方向和 forward PE 的外部对账。

以下猜测字段均被当前代理判为无效字段，而不是“字段有效但公司恰好没数据”：未来 BPS、PB、逐财年 PE、营业利润、EBIT、EBITDA、DPS、CAPEX、经营现金流、FCF、ROA、总资产、总权益，以及 FY4 和猜测的季度预测。因此本轮可以做出的严谨结论是：

- **当前代理白名单已经验证**：收入、净利润、EPS、平均 ROE、未来 12 个月 PE及部分增长/修正序列。
- **当前代理字段映射尚未验证**：未来 BPS/PB、ROA、现金流、CAPEX、FCF、EBITDA和完整预测三表。
- **不能由此断言 Wind 产品本身没有这些数据**：还可能存在不同字段名、不同数据集或本账户未映射的接口；生产前应通过 Wind 代码生成器确定，而不是继续猜字段名。

在当前已验证范围内，未来 BPS、PB、ROA和自由现金流需要由内部三表模型推导：预测净利润进入留存收益，分红和回购进入权益桥，预测期末普通股权益除以稀释股数得到 BPS，再用同一估值日股价计算 PB；ROA 使用预测净利润除以平均总资产；CFO/CAPEX/FCF则必须由营运资本、折旧和投资计划闭合，不能从收入增长率直接拍数。

### 7.5 美股已验证的能力和系统性缺口

Apple 单一样本曾不足以判断是公司缺失还是链路缺失。本轮扩展到 Apple、Microsoft、NVIDIA、Amazon 和 JPMorgan 后，结果高度一致：

| 能力组 | Apple / Microsoft / NVIDIA | Amazon | JPMorgan | 结论 |
|---|---:|---:|---:|---|
| 当前行情与通用估值 11 项 | 9 | 8 | 8 | PB/BPS系统缺失；无分红公司少股息率；银行少通用 ROA |
| 历史财务 13 项 | 8 | 8 | 5 | 科技股有收入、利润、利润率、ROE/ROA、EBIT/EBITDA；银行通用字段更少 |
| FY1—FY3 `west_*` 预测 12 项 | 0 | 0 | 0 | 五家公司全部为空，属于当前链路的系统性覆盖缺口 |

美股原始经营现金流、CAPEX、研发、总资产、总负债、PB/BPS 均未返回；但 EV、部分 EV/EBITDA、P/OCF、ROIC、资产负债率和周转率等供应商衍生值在非银行公司仍可返回。这种“衍生值存在、原始输入缺失”的组合不适合审计建模：它只能用于异常值交叉检查，不能替代原始三表。

Apple 2021—2025 的收入、净利润、EBIT、EBITDA、毛利率、净利率、ROE、ROA 均可返回；Wind 还把它的非自然年财务映射到标准季度槽位。因此即使字段非空，也必须重新核对真实财年结束日，不能把 `rptDate` 直接当公司原始报告期。

因此 Wind 代理在美股最多是辅助核验源，不能替代 yfinance 的原始报表和分析师预期。这里判断的是当前代理和账户组合，不是对 Wind 全产品能力下结论。

### 7.6 字段和报表口径比链路本身更容易造成误判

本轮通过逐字段拆分，确认了几类此前的假失败：

- A 股归母净利润是 `np_belongto_parcomsh`，研发费用是 `rd_exp`，资本开支现金口径是 `cash_pay_acq_const_fiolta`；若按相似名称添加下划线或使用 `fa_` 前缀，服务会报错。
- 未来 ROE 是 `west_avgroe_fy1—fy3`，不是 `west_roe_fy1—fy3`。
- 一个错误字段与多个正确字段合并时，整组请求都会失败。探索字段必须单字段，批量生产只能使用验证后的白名单。
- `wsd` 的季度财务字段曾出现收入、利润、现金流为空而 ROE/ROA有值；同一报告期改用 WSS 后七项均有值。季度三表应优先逐报告期 WSS，不能仅凭一条 WSD 空序列判定没有数据。

内网服务把 Wind 的 `-40522006` 直接写进 HTTP 状态行，Python 将其解释为非法 HTTP 状态；项目包装层随后统一返回 `ErrorCode=-1` 和空表。结果是“字段无效”和“网络失败”在调用方看起来几乎一样。这是代理服务的错误协议问题，不能把 `-1` 直接翻译成 Wind 无数据或无权限。

### 7.7 生产接入边界

用户已解除 Wind 禁止。当前统一公司刷新使用根目录 `WindPy.py` 的固定内网 HTTP 代理，并已完成以下基础接线：

1. 只对两个固定内网地址使用无代理 opener，不关闭全局 VPN，并设置明确连接超时。
2. 当前行情/估值字段使用冻结白名单和单证券请求；市值从人民币元换算为亿元，原始值和公式留痕。
3. A 股合并执行“Wind 有效值优先、Tushare 仅补缺”；manifest 保存每字段 provider、symbol、as_of和方法，数据点按真实来源分别落 source。
4. 旧 one-off Wind 回填脚本继续退役，不能绕过统一 fetch/apply manifest 和 `db_writer`。
5. 未获用户明确授权时，Wind只允许小型请求；全A股历史、全市场截面、分钟长历史及超过活动阈值的任务必须先报告范围和预计数据量并取得permission，禁止拆单绕过。

这次完成的是当前公司快照层，不是完整财务数据仓库。现有多期财务序列模块仍由 Tushare 提供 A 股公告期、报告期与重述字段，尚未与 Wind 历史三表逐字段合并；Wind FY1—FY3 一致预期也尚未写入通用预测层。因此，“Wind 主源”已经是活动合同和当前快照的真实行为，但历史事实层与预测层仍是明确待完成项，不能在交付说明中写成已经全面切换。

仍需后续完善的是代理服务端错误协议、完整历史三表/一致预期的标准化存储、银行保险专用字段字典和请求额度统计。当前服务把部分 Wind 原始负错误码写进非法 HTTP 状态行，客户端只能识别为代理失败；这不影响已验证字段的正常请求，但生产监控应继续区分网络错误、字段错误、权限错误和真实空值。

## 八、Ricequant：官方产品能力与公司内网落地能力

### 8.1 先区分两套完全不同的东西

- **米筐官方 RQData** 是需要官方 SDK 或 HTTP token 的数据产品。当前官方文档覆盖 A 股、港股、PIT 财务、衍生因子和一致预期。
- **公司内网 `ricequant` ClickHouse** 是一个内部数据仓库。`honghu_ricequant_skill.md` 提供的是这个仓库的行情查询说明，不是官方 RQData 账号、SDK 或完整字段合同。

本机没有安装 `rqdatac`、`rqalpha` 或 `clickhouse_driver`。本次没有搜索或读取任何 RQData 官方账户密钥，也没有向 RQData 官方接口登录；内网库使用 skill 已提供的连接配置，通过 ClickHouse 只读 HTTP 接口完成元数据和小样本核验。因此下文“官方能力”来自当前官方文档，“内网实测”才代表现在立即可取的数据。

安全上还需单独处理：本地 skill 文件包含明文内网连接凭证，本报告没有复制这些内容。该文件不得直接进入 GitHub 或部署包；后续应把凭证迁到虚拟机环境变量或受控 secret store，并在任何可能已经推送到远端的情况下轮换凭证。本次只做研判，没有改动该文件或连接配置。

### 8.2 米筐官方 RQData 的历史财务能力

官方[A 股财务文档](https://www.ricequant.com/doc/rqdata/python/stock-mod.html)显示，当前主入口是 `get_pit_financials_ex`：按证券、起止季度和查询日期返回利润表、资产负债表、现金流量表，并保存公告日、报告期和是否来自后续报告重述的标记。参数 `statements='latest'` 取查询时点可见的最新版本，`statements='all'` 保留同一报告期的多次披露，适合 point-in-time 回测。该接口文档明确支持中国内地与香港市场。

对建模最有价值的不是“字段多”，而是以下三点：

1. 原始三表保持季度报告期和公告时点，不需要把今天看到的最终重述值错误地回填到历史回测日。
2. 官方称已提供 200 多个估值、经营、现金流、财务和成长衍生指标，并区分最近财报、最近年报和滚动十二个月口径。
3. 最近 12 期单季度字段使用 `_mrq_n`，最近 9 期滚动十二个月字段使用 `_ttm_n`，最近 9 期年报口径字段使用 `_lyr_n`；`get_factor` 还能把 PE、PB、EPS、ROE、周转率等 PIT 指标按交易日输出。

官方更新履历还显示，旧的 `get_fundamentals`、`get_financials` 和 `get_pit_financials` 已在 2024 年下线。若以后接入，必须按当前 `get_pit_financials_ex`/`get_factor` 合同实现，不能照搬旧教程。

RQData 另有 `current_performance` 和 `performance_forecast`：前者是公司业绩快报，后者是公司对即将到来报告期的业绩预告，可返回收入、净利润、EPS、权益等区间。它们属于公司披露或事件数据，不是卖方一致预期。

### 8.3 米筐官方 RQData 的未来数据比当前主源多在哪里

[一致预期文档](https://www.ricequant.com/doc/rqdata/python/alternative-data)提供两种互补结构：

| 官方接口 | 核心内容 | 时间结构 | 对估值模型的作用 |
|---|---|---|---|
| `consensus.get_comp_indicators` | 一致预期收入、净利润、EPS、净资产、经营现金流、ROE、PE、PS、PB、增长率、目标价和评级 | 每交易日截面；T+1、T+2、T+3及未来12个月 | 可直接形成 A 股多年度市场预期基准，并观察预期随时间变化 |
| `consensus.get_indicator` | 逐机构/逐报告的收入、净利润、净资产、经营现金流、营业利润、营业成本、税前利润、EBIT、EBITDA、EPS、BPS、每股经营现金流、目标价和评级 | 报告基准年 T、T+1、T+2 | 可自行重建机构级一致预期并审查异常报告 |
| `consensus.get_price` / `get_security_change` | 目标价、评级、盈利预测上调/下调 | 报告事件或周/月/季统计 | 用于判断预测方向、拥挤度和修正速度 |
| `consensus.get_factor` / `get_analyst_momentum` | 一致预期基础、成长、估值因子及 1周至数月的预测动量 | 日频截面和滚动窗口 | 适合做预期修正因子，不应直接当成财务报表事实 |

这套文档能力明显补上了当前数据缺口：未来净资产和 BPS 可以支持 forward PB，未来经营现金流可用于现金流质量判断，未来 ROE 可以交叉核验利润与权益。但公开字段表仍没有标准的未来 CAPEX、自由现金流或未来 ROA；即便以后接口有更多可选因子，也应先用实际账户字段清单和样本返回验证，不能根据产品宣传推定。

两个时点问题必须在接入前锁死。第一，`T` 是接口返回的最近年报基准年，不能机械等于抓取日所在自然年；所有 T+1/T+2/T+3 都要先映射到明确财年。第二，`report_range=0` 的历史值可能因供应商修复而变化，官方提示需要历史不变时使用 `report_range=3`；研究生产仍应保存每次原始返回和抓取时间，不能假设在线查询结果永久不变。

公开文档的财务入口明确写中港股，一致预期示例和参数以中国内地市场为主；没有找到美股财务或 AAPL 类证券的正式合同。因此 Ricequant 不能列入美股候选主源。

本轮进一步读取米筐官方发布的“一致预期因子”工作簿。四类工作表合计 519 项：基础财务 103 项、估值 46 项、成长 150 项、情绪与修正 220 项。它比接口说明更清楚地显示了可用于建模的结构：

- 基础财务覆盖基准年、未来一至三年和未来 12 个月的净利润、EPS、营业收入、营业成本、营业利润、ROE、经营现金流、净资产及增长率。
- 估值覆盖相同期限的 PE、PB、PS、PCF，以及 PEG 与相关评分。
- 成长和修正覆盖未来一至三年的利润、EPS、收入、成本、营业利润、经营现金流、净资产、ROE在 7/14/30/60/90 日窗口的变化。
- 情绪类还包含预测偏离和市场信心，但它们是分析师行为信号，不是财务报表事实。

这意味着：**如果官方完整因子链路可以合法接入并通过样本验证，RQData 可能是 A 股结构化一致预期最宽的数据源。** 但这仍不是当前内网可用能力；当前内网两张分析师视图只映射了其中很窄的一部分，不能把官方 519 项写成项目已经能取到。

|---|---:|---:|---|

过去一年内，`stock_analyst_consensus` 至少一次出现代表性年度 30 日 ROE/ROA值的证券约3329只，季度口径约3061只；`stock_analyst_adjustment` 三个预测序号有值的证券约3032—3034只。贵州茅台、宁德时代、招商银行和紫金矿业均能取得部分窗口样本；个别公司在 30 日窗口为空但 90/180 日窗口非空，说明空值需要解释为“近期没有进入该窗口的有效分析师信号”，而不是公司完全没有一致预期。

这两张表最重要的边界是：它们都是宽表因子，不是绝对财务预测。没有字段字典时，`0/1/2` 不能直接写成 FY1/FY2/FY3，`aa_ew` 也不能直接解释成盈利上调百分比。接入建模前应向表维护方取得公式、预测期限映射、单位、原始机构池、更新时点和是否历史回补的正式合同。

贵州茅台样本从 2021Q1 到 2026Q1 可以恢复 21 个报告期的“首次可见日—下一份财报前最后携带日”，说明 ASOF 设计确实能支持按当时已知信息回测。但标准模型接入前仍有五个必须解决的问题：

1. `date` 是交易日，`report_date` 才是财报期；如果直接按 `date` 计数，会把同一份财报重复数十次。
2. `stock_fina_indicator` 的来源是 Tushare，和项目直接调用 Tushare 属同源，交叉验证时不能算两个独立来源。
3. 建表字段没有单位和币种注释，股本、绝对金额和比例不能仅凭列名入模。
4. 大额财务数值存为 `Float32`，会损失精确到元的有效位；模型底稿应转为明确单位后的高精度数值，而不是把显示值当审计数。
5. 缺失值同时存在 `NULL` 和 `NaN` 两种形态，读取层必须统一做有限数检查。

### 8.5 Ricequant 应怎样进入后续架构

权限问题已经解决，但能力边界仍决定它不能单独成为完整财务供应商。内网 `ricequant` 最合理的角色是：

- A 股/港股行情的本地高速镜像；
- A 股 Tushare 财务指标的按公告日展开缓存；
- 在明确底层来源、单位和更新 SLA 后，为回测提供 PIT 快照；
- 用 ROE/ROA一致预期判断市场对资本回报的预期方向；
- 用分析师调整特征补充盈利修正动量，但不直接生成收入、利润或目标价。

如果希望真正利用米筐的差异化能力，下一步不是再申请这两张表权限，而是让数据团队把官方完整一致预期能力以受控视图或接口映射进来。首轮只测试一只证券、一个截面和十余个字段：T+1 至 T+3 的收入、净利润、EPS、净资产、经营现金流、ROE、PE、PB、估计时点，以及从逐机构明细复算的机构覆盖数。字段值、单位、预测财年映射、历史不变性和权限通过后，才能把它作为 A 股预测主候选；否则当前两张表只能作为因子补充层。

## 九、数据源能力矩阵与“谁最全”的回答

“实测可用”表示当前账户和链路的小样本确实返回；“官方潜力”只表示文档/字段表存在，不能直接进入模型。

| 数据源/链路 | A 股历史与当前 | A 股未来 | 美股历史与当前 | 美股未来 | 最合适的角色 |
|---|---|---|---|---|---|
| Tushare | 长历史三表、财务指标、日频估值和公告时点，实测可用 | 逐机构 `report_rc` 到未来三年，收入、利润、EPS、PE、ROE、EV/EBITDA等需自行去重聚合 | 官方有接口但当前账户无权限 | 当前不可用 | A 股实际值主源；最可审计的 A 股逐机构预测底稿 |
| yfinance | A 股约4—5年报表和当前估值，预测覆盖不稳定 | 仅适合补充 | 美股约5年年报、5—6季报表、当前估值，实测完整度最高 | FY0/FY1收入、EPS、修正、评级和目标价 | 美股主源；A 股应急核验 |

### 9.1 分市场和用途的完整度排名

没有一个“全市场万能第一名”，需要按问题排名：

1. **A 股标准化历史实际、当前估值和近三年聚合预测：Wind 第一。** 它的机构级数据治理和六类样本覆盖更适合作为主字段值；公司公告和交易所披露才是最终权威，Tushare用于补缺和回到公告/重述口径复核。
2. **Tushare最独有的价值是逐机构与可审计底稿，而不是重复的当前估值。** `report_rc` 能检查机构池、重复报告、离散度和报告时点，原始三表保留公告/更新字段。Wind聚合与Tushare重建结果应对账，不能简单平均。
3. **A 股未来预测的潜在最宽结构：完整 RQData。** 它在官方字段表中还覆盖净资产、经营现金流、PB/PCF和大量修正因子；但当前内网未映射这些字段，所以现阶段不能给它“可用第一名”。
4. **美股：yfinance 第一且当前没有接近的替代。** Tushare账户没有美股权限，Wind代理在五只样本中缺原始现金流、CAPEX、研发、资产负债表和三年预测，Ricequant没有美股。
5. **三年以上远期和行业经营变量：四个源都不够。** 产量、ASP、产能、利用率、良率、门店、用户、ARPU、储量、订单、临床成功率等仍需公告、IR、行业数据库和独立研究，再由内部模型转成财务结果。

“多个供应商都返回同一卖方预测”并不等于多条独立证据。Wind、Tushare和 RQData 可能收录相同研报，跨源一致只能证明供应商处理结果接近，不能把置信度机械乘三。真正的差异价值在于：Tushare保留逐机构明细，Wind提供方便的聚合及历史修正，Ricequant若完整接入可补充未来净资产、CFO和预期动量。

### 9.2 用户特别关心的未来指标

| 指标 | 当前直接可得 | 应怎样进入正式模型 |
|---|---|---|
| 收入、净利润、EPS | A 股 Wind FY1—FY3、Tushare逐机构 FY1—FY3；美股 yfinance FY0/FY1 | 先冻结独立经营预测，再与一致预期逐项对账；三年以上由内部模型生成 |
| forward PE | Wind未来12个月、Tushare报告行、yfinance info；完整 RQData 文档有多期限 | 统一用同一估值日股价除以同一预测截面稀释 EPS复算，供应商值只作核验 |
| forward ROE | Wind A股 FY1—FY3；Tushare部分报告；内网Ricequant有ROE特征；完整RQData有多期限 | 用预测归母净利润除以平均普通股权益复算，并解释供应商口径差异 |
| forward ROA | 当前没有稳定的绝对序列；内网Ricequant只有未完整解释的ROA特征 | 用预测净利润除以平均总资产，由预测资产负债表生成 |
| forward BPS/PB | 当前已接链路没有直接验证；完整RQData字段表有未来净资产/PB | 期末普通股权益除以稀释股数得 BPS，再用统一股价算 PB |
| forward CFO | 完整 RQData字段表有一致预期经营现金流，但当前内网未映射 | 内部模型仍应从净利润、非现金项目和营运资本复算，用外部值对账 |
| forward CAPEX/FCF | 四个当前链路均未验证通用直接序列 | 从产能计划、折旧、固定资产和营运资本建立现金流桥，不允许按收入固定比例静默拍数 |
| forward EV/EBITDA | Tushare部分报告有；其他当前链路没有完整多期限序列 | 用统一企业价值桥和预测 EBITDA复算，避免混用不同债务和现金口径 |

所以，“Wind是否没有现金流、CAPEX、研发、PB/BPS及三年预测”的准确回答是：**A 股历史现金流、CAPEX、研发、PB/BPS都可以取得；A 股 FY1—FY3收入、净利润、EPS和ROE也可以取得。尚未验证的是未来 BPS/PB、ROA、现金流、CAPEX和完整预测三表。美股则确实在当前代理的五只样本中系统性缺少这些原始字段和三年预测。**

## 十、适合综合财务建模的多源架构

### 10.1 不选择一个万能源，而是给每类数据指定主源

建议把数据分成七层，禁止在一张“估值输入表”里混合：

1. `actual_reported`：公司已披露的历史三表与公告时点；
2. `market_data`：价格、股本、市值、利率和历史估值；
3. `vendor_consensus`：带估计截面、预测财年、机构数和分布的市场预测；
4. `management_guidance`：公司区间指引、订单、产能和资本配置计划；
5. `industry_driver`：量、价、份额、产能、利用率、客户和行业总量；
6. `internal_model`：独立经营预测、三表联动和估值结果；
7. `market_implied`：当前价格反推的利润、增长、ROIC或终值条件。

同一个指标可以有多条观测，但必须指定一个 canonical 主值并保留其他来源用于对账。实际财报不能跨供应商平均；若两源不一致，应追查重述、合并口径、单位、公告日和字段定义。预测也不能在财年和机构池未对齐时平均。

### 10.2 推荐的实际分工

| 数据层 | A 股 | 美股 | 为什么 |
|---|---|---|---|
| 历史三表和公告时点 | Wind 标准化主值；Tushare补缺并复核公告/重述；重大冲突回公司披露 | yfinance 主源，SEC/IR重要项核验 | 同时兼顾Wind数据治理与Tushare明细审计 |
| 当前估值和行情 | Wind 主源；Tushare只补 Wind 缺失的可比字段 | yfinance | 当前公司刷新已按字段保留实际来源和时点 |
| 近三年市场预测 | Wind聚合值 + Tushare逐机构重建；Ricequant ROE/ROA和调整信号辅助 | yfinance FY0/FY1 | 同时保留方便性、可审计性和修正方向 |
| 预测净资产/CFO/PB/PCF | 优先推动完整 RQData映射；在此之前由三表模型生成 | 内部三表模型 | 当前直接数据缺口最大 |
| 三年以上预测 | 内部经营驱动与三表模型 | 内部经营驱动与三表模型 | 供应商一致预期远端覆盖不足且可靠性下降 |
| 行业经营变量 | 公司公告、IR、行业数据库、研报和独立公开搜索 | 同左 | 通用财务供应商无法提供所有行业驱动 |

这是一套互补架构，不是四源大杂烩。Tushare与内网财务快照同源，不能算独立核验；Wind与Tushare的一致预期也可能来自同一研报池。系统要保存供应商来源和底层机构来源两层标识，避免把转载或重复收录当成多方确认。

### 10.3 模型复杂度必须由数据决定

用户给出的理想体系方向正确，但需要把“可获得什么”变成强制路由：

| 模型等级 | 最低可得数据 | 可以做什么 | 不允许做什么 |
|---|---|---|---|
| Level 1 业务驱动 | 产品量价、产能/用户、成本、毛利和三表 | 产品/分部自下而上模型、完整三表和现金流 | 缺少关键量价时自行补单点 |
| Level 2 行业与份额 | 行业空间、份额、产能、利润率和历史三表 | 市场空间×份额与财务桥交叉验证 | 把行业增长全部归给公司 |
| Level 3 财务桥 | 历史三表、订单/指引、市场预测、同行 | 收入—利润率—营运资本—CAPEX桥 | 输出伪精确的产品级出货量 |
| Level 4 外部基准与反向模型 | 历史实际、近端一致预期、价格和股本 | 一致预期调整、反向利润/DCF、阈值分析 | 强行预测五至十年单点利润 |

目前四个通用供应商足以让多数上市公司达到 Level 3；只有在行业经营数据另行补齐后，才可能达到 Level 1。数据源字段很多，不等于经营模型已经具备关键输入。

### 10.4 不同公司类型还需要哪些额外数据

| 公司经济类型 | 通用财务源能解决 | 仍需专项补充 |
|---|---|---|
| 消费与成熟制造 | 三表、利润率、周转、CAPEX、ROE和一致预期 | 销量、提价、渠道库存、单店/单品、份额 |
| 科技硬件与半导体设备 | 历史研发、CAPEX、利润率和近三年盈利预测 | 出货量、ASP、产品代际、客户资本开支、产能、良率、订单 |
| 强周期与资源 | 历史现金流、资本开支、杠杆和中周期利润 | 商品价格、产量、储量、品位、单位成本、新增供给 |
| 银行和保险 | 通用利润、权益、ROE和估值只能做骨架 | 净息差、不良率、信用成本、资本充足率、内含价值、新业务价值等专用表；当前仅不良率经过 Wind 实测 |
| 公用事业与基础设施 | 资产、债务、现金流、分红和历史回报 | 监管回报、电价/费率、利用小时、特许权和在建项目 |
| SaaS与平台 | 收入、现金、费用和近端一致预期 | ARR、留存、ARPU、获客成本、GMV和货币化率 |
| 生物医药管线 | 现金消耗、研发、亏损和市场预测 | 临床阶段、成功概率、适应症市场、专利期、里程碑和商业化成本 |

因此银行、保险、资源、SaaS和生物医药不应只因通用字段非空就套普通制造业模板。Wind对招商银行的横截面已经证明这一点：缺少通用毛利和EBITDA是经济口径问题，不是需要补零的数据质量问题。

### 10.5 独立估算与市场对账的正确顺序

1. 用历史实际、管理层已披露事实和行业驱动完成独立预测，冻结假设与结果哈希。
2. 再读取 Wind/Tushare/yfinance/RQData 的市场预期，逐项比较收入、利润率、净利润、EPS、CFO、净资产和估值。
3. 差异明显时只围绕差异最大的经营变量补查事实和会计口径，不自动向一致预期靠拢。
4. 只有发现新事实或模型错误才修改独立结果，并保存修改前后假设、原因和证据。
5. 复查后仍成立的差异才进入预期差判断；不能解释的差异只能叫“未解释模型分歧”。

外部一致预期的作用是 benchmark，不是答案。内网 Ricequant 的预测修正可以提示“市场最近是否在改变看法”，但没有绝对金额时不能告诉模型利润应该是多少。

### 10.6 三表和估值必须闭环

最核心的跨表关系应统一实现，而不是让每个研究员临时写公式：

```text
经营现金流 = 净利润 + 非现金费用 - 营运资本增加 + 其他经营调整
自由现金流 = 税后经营利润 + 折旧摊销 - 资本开支 - 营运资本增加
期末权益 = 期初权益 + 归母净利润 - 分红 - 回购 + 增发及其他权益变动
```

由此才能一致地得到未来 BPS、PB、ROE、ROA、净债务和 DCF现金流。每股估值还要满足“股价÷EPS=PE、股价÷BPS=PB”；企业价值要从市值加债务、租赁、优先股和少数股东，再减现金与非经营投资。三条桥中任一条对不上，模型不应发布。

## 十一、统一数据合同和质量控制

每个财务观测至少保存：

```text
issuer_id / security_id / market / currency
metric / value / unit
fiscal_period_start / fiscal_period_end / fiscal_year / fiscal_quarter
period_basis = single_quarter | ytd_cumulative | fiscal_year | ttm | mrq
accounting_standard / consolidation_scope / restatement_status
data_kind = actual | consensus | guidance | industry_driver | internal_model | market_implied
announcement_date / estimate_as_of / market_price_as_of / fetched_at
provider / provider_field / underlying_source_or_institution
analyst_count / estimate_mean / median / low / high / dispersion
calculation_formula / input_refs / quality_flags
```

预测层还必须保存目标财年而不只保存 `FY1`。Tushare `report_rc` 应按“机构＋目标财年＋指标”保留截面日前最新记录，再计算中位数、均值、高低值、机构数和中位绝对偏差；Wind预聚合值与该结果对账。yfinance 的 `0q/+1q/0y/+1y` 也要先映射真实财季和财年结束日。

最容易造成巨大偏差的质量问题包括：把累计季报当单季；把不同日期的股价、EPS和BPS混算；忽略ADR、拆股和稀释股本；把供应商FCF混同内部FCFF；用最新重述值回填历史回测；把内网Tushare镜像当第二个独立源；以及把 `NULL`、`NaN` 或不适用字段补成零。这些都应进入自动门禁。

## 十二、建议的实施顺序

用户已授权解除 Wind 禁止；本轮已修改数据源合同和当前公司快照代码，但没有运行全公司抓取、没有生成 live fetch manifest，也没有写数据库。后续实施建议按以下顺序：

1. **完成历史事实层。** A股以Wind标准化字段为主，Tushare仅补缺并保留公告/重述审计，美股以yfinance为主；所有原始快照、报告期、单位、币种和重述状态不可变保存。
2. **建立A股一致预期双轨。** Wind FY1—FY3聚合值作为市场基准，Tushare `report_rc`重建逐机构中位数、离散度和修正轨迹；差异追查机构池与时点，不做平均。
3. **澄清并接入内网Ricequant信号。** 先取得144个ROE/ROA字段和12个调整字段的正式字典；在此之前只作研究信号，不进入金额模型。
4. **评估完整RQData映射。** 如果能把未来净资产、CFO、PE/PB/PS/PCF及逐机构明细映射到内网，它将显著降低A股预测资产负债表和市场对账的外部数据缺口。
5. **建立三表联动引擎。** 实现利润、营运资本、CAPEX/折旧、债务、税、权益和现金流闭环，生成forward BPS/PB/ROA/FCF，而不是依赖供应商是否恰好提供。
6. **建立模型选择与降级路由。** 按公司经济类型、数据可得性和行业经营变量选择Level 1—4，并计算所有经济上适用、数据足够的模型，不机械平均。
7. **建立独立估算冻结和外部对账。** 先独立建模，再读取一致预期；差异复查、假设变更和预期差结论全部留痕。
8. **最后做前端集成。** 页面展示数据层、模型角色、结果区间、外部基准、差异来源和证伪条件，并可追溯到具体输入和来源。

## 十三、最终建议

如果必须现在给出最明确的选型：

- **A股标准化历史、当前估值和近三年聚合预测选 Wind 作为主源。** 当前内网 HTTP 代理的小样本覆盖已经支持这一判断；Tushare不应无差别重复覆盖Wind非空值。
- **Tushare作为字段补缺和审计源。** 它最重要的独有增量是逐机构 `report_rc`、公告日期、报告类型和重述/更新字段；Wind缺失时可补当前值，两源冲突时保留双方并回查公司披露。
- **如果官方完整 RQData 能映射进内网，它可能成为 A股预测字段最多的结构化源。** 但在未来净利润、收入、净资产、CFO、PE/PB等字段实际返回并完成单位/PIT验证前，只能列为下一阶段候选。
- **美股选 yfinance。** 当前其他三条链路都不足以替代；重要模型输入应再回到公司IR/监管披露核验。
- **三年以上、行业驱动和完整预测三表必须由内部模型承担。** 外部预测用来对照、发现差异和校准范围，不应替代经营传导。

最终最好的方案是“Wind A股主字段＋Tushare补缺/逐机构审计＋yfinance海外＋行业事实＋内部三表模型”。这不是简单拼表：每个字段只能有一个当前主值，补缺必须有原因，冲突必须留痕，底层同源研报不能被重复计作独立证据。
