# 数据呈现与研究写作标准 V2

本文件只规定面向研究员的表达和展示，不提供可套用正文模板。活动流程见 `docs/research/RESEARCH_WORKFLOW_V2.md`；旧版在 `archive/project_history/retained_originals/workflow_v1_20260712/templates/数据呈现与重写标准.md`。

## 1. 正文

- 每个页面独立回答一个明确问题。
- 事实后写口径、冲突、含义和结论边界，不把 source、表格或 JSON 留给读者自行拼接。
- 指标必须解释为什么设计、如何计算、权重或分母为何合理、结果代表什么。
- 同名或近似命名的指标若使用不同输入、分母或阈值，必须分别命名并解释，不能在正文中混成一套结果。专家判断应明确标注非外部事实、残差计算和校准边界；被正文引用的本地计算底稿必须以文件内容哈希随研究包冻结。
- 反方不是独立的形式章节，而是要实际改变基准结论、情景概率或跟踪优先级。
- 禁止跨行业/公司/指标复用同一段，只替换名词；禁止“它不是孤立数字”等固定句式。
- 篇幅下限来自机器配置，是浅薄输出报警线，不是要求凑字。
- 每个研究章节默认完成“问题 → 证据/数据 → 方法（如有）→ 分析与结论 → 需要补充的信息”这条链。允许自然行文，不得把这些词机械复制成每节模板，也不得用字段完成状态或审计术语代替分析。
- “没有直接证据”“公开资料不足”“无法根据现有资料推断”必须按实际情况区分；不得统一贴“未知”标签。结论写清主体、期限、事件和影响，避免缺主语的“决策含义”“破坏程度”“专属边界”。
- 写“客观不可得”前至少完成一次针对缺口的二次检索或原始文件复核，并说明查过的来源类型、为什么仍不可得、可接受的代理以及对结论的影响；不能把 producer 尚未抓取写成客观不可得。
- 当前判断优先使用最新完整年度和最新可得报告期；较旧资料只在说明历史结构或长期趋势时使用，并明确时效边界。每个核心数字都应能回到 URL/PDF 定位、原文摘录或可复算底稿，并经过单位、币种、期间和数量级核对。
- 行业或产品边界要让未参与项目的研究员也能判断“包含什么、不包含什么、处于价值链哪一环、收入/份额口径为何可比”，不能用内部分类名替代解释。

## 2. 表格

- 表头和内容按语义分配宽度：状态、排名、日期、分数短；来源、原文、判断、证实/证伪、交易框架长。
- 宽表只在局部容器横向滚动，不造成整页溢出；长表应有顶部同步滚动条。
- 同一表中口径、币种、财年和预测/实际必须可区分。
- CR、份额、TAM 和财务表必须写主体、期间、单位和来源。
- 市占率和 CR 只能在同一市场边界、期间、币种/单位及分母下相加；公司业务构成、集团与子公司、产品收入与行业收入必须分开。无法统一口径时并列展示并解释，不制造伪精确排名。
- 字段单位和显示单位不同时，先换算数值再改标签；不得把“十亿美元”的原数值直接标成“亿美元”，也不得把“百万个”的原数值直接标成“万个/亿个”。关键结果用“数量 × 单价 = 金额”或等价量纲做一次反算，并把换算纳入测试。
- 空值必须显示具体原因，不使用空白占位。
- 表格有信息价值门槛：每张表回答一个已写明的问题；删除某列不影响事实理解、计算复核或决策时，该列应删除；两张表回答同一问题时应合并。字段完成度、输出覆盖、参数 owner、内部状态和审计清单只留在底稿或 API。
- 场景、变量和模型缩写必须改成读者无需查表即可理解的中文名称。最后一列不得被裁切，也不应承载无法横向比较的长篇结论。

## 3. 财务和估值

- 市值、经营现金流、capex、估值和融资额默认“亿元人民币（约 xx.xx 亿美元）”。
- PE/PB/PS、毛利率、净利率、ROE/ROA 保留两位小数。
- A 股用 Tushare；海外、台股、日股等用 yfinance。接口原值和汇率口径保留在底稿。
- 亏损 PE 不适用、私营/子公司不可得、接口缺失和未补抓必须分开写。
- 财务专题把估计方法、关键假设、未来结果、差异原因和结论放在中心。历史数据和未来情景分别优先合并为一张高信息表。减少低信息表格不等于取消表格：模型结果需要横向比较主体、情景或期限时，应使用未来影响表直观呈现，再用正文解释差异；敏感性只有在增加决策信息时才用一张表，否则用更清楚的量化正文。大面积相同数值必须复算并解释。
- 多家公司只有在口径和经营逻辑真正可比时才合表；基数、现金转换或风险传导不同，应分别展示核心财务和情景结论。复杂公式必须紧邻列出关键数值输入、依据与代入结果，不能只给公式不给参数；本地材料缺少重要的未来盈利、市场估值或资本回报对账时，应继续检索可核验的最新外部资料。

## 4. 引用

- 数据和可核验事实在句尾使用 `^src:<id>`；多个引用之间留空格。
- 来源索引放文档最后；索引标题、发布方和日期应可读。内部 source id、记录号、表名和机器定位字段不单独成列。
- 已建立规范公司身份的上市公司，在每个独立正文段落第一次出现时链接到 `/company/<company_id>`。供应商调用失败、代理错误、重试和逐字段补缺属于内部生产记录；公开正文只保留会改变研究结论的数据缺口及影响。
- source excerpt 必须与当前指标语义对齐，不能把同一财务摘录复制到技术、层数、客户等无关指标。
- 英文来源保留英文原文，并由研究生产阶段显式写中文标题和译意；不得用自动占位说明冒充翻译。2024 年或更早材料作当前判断时显示严重时效警告。
- 正文不暴露裸 URL、本地路径、`opp://`、`source_ref:` 或原始 JSON。

## 5. 图表

- 只有趋势、结构、比较或关系能从图中获得额外信息时才画图。
- 长期序列直接画完整序列；单点和两三个点不强行可视化。
- 图表在渲染前按主体、指标、报告期和口径去重，不能让 legacy/normalized 等兼容记录在同一坐标重叠。表格按内容语义设置列宽；公司名、时间标签和关键结果必须在桌面与移动端直接可读。
- 横纵轴、单位、期间、来源、实际/预测和口径必须完整。
- 图表正文解释“数据是什么、覆盖时间、怎么看、对判断意味着什么”。
- 图片需检查尺寸、非空像素、移动端缩放和文字重叠。

## 6. 页面结构兼容

写作与数据呈现标准只决定既有页面中的内容组织，不自动授权改变页面集合、导航、路由、页面分工或交互。除非用户明确要求改版，同一产品不同 run 默认复用该产品的活动页面合同；内容深度和章节表达可以自适应。C 轨页面合同来自顶层四份基础协议、`MODULE_CONTEXT.md` 和 `HUMAN_READABILITY_STANDARD.md`，不是从某几个历史 run 的页面外观归纳。

现有 viewer 仍使用主文档、Q0-Q5、可选 Q6、公司透视、估值和产业链。成熟行业包用于校准深度、证据密度和表达质量，不允许照抄标题、句式或段落节奏。

C 轨主报告只概括跨主体结论并链接实体/标的详细页，不得把同一详细正文同时复制到主报告和子页面。

默认篇幅兜底下限保存在 `config/research_workflow.yaml`。若用户要求更高或成熟范本同类页中位数更高，执行更高标准；如果行业极窄或资料客观不足，必须在审计中解释，不能用重复文本补足。

## 7. 验收

- 写作 reviewer 检查问题链、证据链、逻辑链、表达链和反方链。
- writing reviewer 内的 citation verification 检查引用存在、句间绑定和 excerpt 语义一致；`citation` 是核验方法，不新增非 canonical reviewer stage。
- science reviewer 独立复算 CAGR、CR、份额、同比、贡献率、单位换算和敏感性。
- financial reviewer 检查上市公司完整性和不可得原因。
- browser reviewer 用真实浏览器覆盖桌面/移动、所有 tab、source 弹窗、表格滚动和图片像素。
- writing reviewer 必须拒绝公开正文中的机器字段、内部代码、重复低信息表格、未解释概率术语和公式源码。
- browser reviewer 必须逐表滚到左右两端，检查最右列表头/单元格完整可见、无重叠裁切且整页无横向溢出，并保存每张表最右端局部截图；只验证存在滚动容器不算通过。每个路由的全部唯一证据按钮还要用键盘实际打开，核对 API、抽屉内容、可读日期/来源级别、机器字段和抽屉溢出。
- 成熟研究包只校准五条链——问题、证据、逻辑、表达和反方——不复制标题、段落节奏或固定表格。字符数按真实 Unicode 实质正文统计，来源索引和 frontmatter 不计入；篇幅、引用数和表格数都不能代替独立复算与浏览器实测。
